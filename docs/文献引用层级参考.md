在计算机科学（CS）顶级会议和期刊的写作中，**文献引用（Citation Strategy）不仅是学术规范，更是构建研究“合法性（Legitimacy）”和“学术定位（Scholarly Positioning）”的核心手段**。

审稿人（Reviewer）往往会先通过 Reference 列表来判断作者对该领域研究前沿的掌握程度以及工作定位。以下针对您提到的关键问题，梳理计算机类论文“分层引用”与文献配比的一般方法：

---

## 一、 文献引用的核心组成与黄金比例

计算机科学是一个快节奏且极其看重会议（Conference-First）的领域。一篇标准 CS 顶会论文（以 8~10 页为例，参考文献通常在 30~50 篇之间）的文献构成建议如下：

```
[顶会/顶刊正式发表]  ■■■■■■■■■■■■■■■■■■■■ 60% - 70% (基石与可信度)
[arXiv 预印本]         ■■■■■ 15% - 25% (前沿性与新领域)
[经典综述/基础理论]   ■■■ 10% - 15% (背景支撑)

```

### 1. 正式发表论文 vs. arXiv 预印本比例

* **黄金区间**：**正式发表论文 60%~70%**，**arXiv 15%~25%**。
* **底线原则**：**正式发表（Peer-reviewed）论文必须占绝对主导**（通常不低于 60%）。如果 arXiv 占比超过 35%~40%，审稿人极易质疑论文的学术严谨性，怀疑作者没有认真梳理已被同行评审检验的既有研究。但是如果被顶会follow-up的arxiv文献，说明已经获得社区认可，可以保留。
* **作者机构原则**：例如：OpenAI、Anthropic、Google DeepMind、Stanford、Berkeley、CMU等知名研究机构的technical report，即使0 citation也可能值得引用。

## 二、 像 Agent 安全这种新兴领域的引用策略

对于大模型智能体（LLM Agent）、Agent Security（如 Prompt Injection, Jailbreak, Tool/API Exploitation, Agent Hijacking）等**演进速度极快的新兴交叉领域**：

1. **“基石-前沿”双层映射法**：
* **下层（传统 security/CS 顶会）**：引用传统系统安全/软件安全/AI安全的顶会（S&P, USENIX Security, CCS, NDSS, IEEE T-IFS）以及 AI 顶会（ACL, NeurIPS, ICML, ICLR）的**基础方法论**（如：System Security, Automated Fuzzing, Sandbox Isolation, Red Teaming 等概念）。
* **上层（最新 arXiv）**：引用近 3~12 个月内针对 Agent 特有安全问题的最新预印本。


2. **追溯 Peer-reviewed 的同源工作**：
* 许多 Agent 安全论文虽然看起来是全新的，但其底层思想往往衍生自传统 LLM Security 或 Automated Vulnerability Auditing。**必须把根基挂载在已发表的传统顶会上**，证明该研究方向的学术脉络，而不仅仅是“热点拼接”。

## 三、 arXiv 未正式发表文献的引用门槛与筛选条件

在 arXiv 上，每天有海量未经评审的论文。引用 arXiv 论文时，需要满足以下条件之一：

| 条件类型 | 具体指标 / 筛选标准 | 引用合理性说明 |
| --- | --- | --- |
| **高引用量/影响者** | 被引量到达一定规模（如 $\ge 20 \sim 50+$ 次引用，视领域细化程度而定） | 已经被社区广泛认可为 SOTA 或 Baseline。 |
| **知名团队/实验室** | 出自顶级高校（如 CMU, Stanford, UC Berkeley）或顶尖机构（如 OpenAI, Anthropic, Google DeepMind） | 质量经过机构内部 Peer Review，权威度高。 |
| **直接 Baseline (直接对手)** | 哪怕只有几位数引用，但**其提出的方法/工具与你的工作直接冲突或重合** | 必须引用并做对比，避免被审稿人指责“隐瞒已有的相同工作”。 |
| **发布时间极近** | 3 个月内刚刚发布在 arXiv 上的最前沿相关工作 | 证明领域最新进展，不受引用量低的影响。 |

> **提示**：如果一篇 arXiv 论文发表超过 1~2 年，**既没有被任何会议/期刊录用，引用量又极低（< 5 次）**，尽量避免引用；除非它是唯一提出某种特殊机制的文献。

## 四、 顶会顶刊 vs. 次级会议/相关性强论文的平衡策略

这是论文写作中最常碰到的权衡问题：**“相关度略低但名气极大的顶会论文” vs. “相关度极高但发表在普通期刊/次会/arXiv 的论文”**。

### 最佳方案：分工定位（不要二选一，而要各司其职）

```
                     ┌── [顶会顶刊 (相关性一般)] ───► 负责“立意与理论支撑”
                     │                                 (如放在 Introduction / Overview)
【引用文献组合】 ──┤
                     │
                     └── [次会/arXiv (相关性极强)] ──► 负责“对比与局限性分析”
                                                       (如放在 Related Work / Experiment)

```

1. **引言（Introduction）与方法论（Methodology）阶段**：
* **优先引用顶会顶刊（A类）**：用于建立宏观背景、定义问题的重要性、引入核心理论或支撑技术（如代码属性图 CPG、静态分析理论等）。这能给审稿人一种“这项工作站在巨人肩膀上”的信心。


2. **相关工作（Related Work）与实验对比（Experiments）阶段**：
* **必须引用相关性最强的工作**（即便它是 B/C 类会议、普通期刊或 arXiv）：在学术道德和严谨性上，**相关性 > 论文级别**。如果故意漏掉最相关的次级会议论文，被熟悉该方向的审稿人发现后，通常会被直接给拒稿（Omission of Closely Related Work）。

## 五、 综述与具体方法论文的占比平衡

* **黄金比例**：**具体方法论文 80%~90%**，**综述论文（Survey/Review） 10%~20%**（通常控制在 3~5 篇以内）。
* **引用原则**：
* **综述的作用**：综述用于在 Introduction 或 Related Work 开头**快速概括整个子领域的发展全貌**（例如：*“For a comprehensive survey on LLM Agent vulnerabilities, see [X]...”*）。
* **禁忌**：**切忌用综述代替原始文献**。如果你要引用某个具体的攻击手段、漏洞利用技术或防御框架，必须引用**最初提出该方法的原始论文**，而不是引用总结它的综述。

## 七、 总结：分层引用的实战落地指南

在实际撰写论文的 `Related Work` 部分时，建议采取以下**三层推进法**：

1. **第一层（基石层 - 顶会顶刊为主）**：定义领域上层范式（如安全领域的 S&P/USENIX/CCS/NDSS，AI 领域的 NeurIPS/ICLR/ACL）。
2. **第二层（分支层 - 顶会+高质量/高引 arXiv）**：介绍与本文最贴近的技术分支（如 LLM-based Security, Code Analysis & Graph Neural Networks 等）。
3. **第三层（靶心层 - 强相关文献，含最新 arXiv 与细分会议）**：直接锁定与本文解决**同一特定子问题**的工作，详细展开说明它们与本文在技术路径、假设前提或效果上的差异。
