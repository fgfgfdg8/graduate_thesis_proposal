## 1. 研究内容解析

本课题的主线是：**单一源文档经目标系统摄入分块后形成多个检索单元，由此产生的同源互补投毒风险，以及检索后、生成前的上下文安全防护**。

| 层次 | 报告中的内容 | 插图必须准确表达的含义 |
|---|---|---|
| 核心问题 | 文档级摄入与块级检索的粒度差异 | 一个攻击者可修改的长文档，经过系统分块，产生两个具有互补作用的检索块；单文档不等于单文本块。 |
| 研究点一 | 基于同源多文本块协同的分布式投毒攻击框架 | 先构造和验证双块互补语义，再固定核心及背景句，仅优化外围触发器，提高不同分块视图下的共同召回能力。 |
| 研究点二 | 基于检索上下文表征分析的检索增强生成安全防御方法 | 统计筛选与跨块关系检查产生待审集合，结合异源参照文本按需调用一次判别 LLM，移除判为投毒的块。 |
| 统一评价 | 攻击、防御、迁移和消融实验 | 同时评价攻击效果、防御后安全性、正常问答效用及计算开销；不能只画攻击成功率。 |
| 原型应用 | RAG 投毒攻防联合测试系统 | 五个主要模块：攻击测试、防御测试、日志记录、可视化、数据库；共享知识库、检索器、生成器和评价接口。 |

### 1.1 威胁模型的硬边界

1. 每个目标查询仅允许篡改**一篇**源文档，不能把两篇独立恶意短文档直接注入为两个检索块。
2. 攻击者知道目标查询与正确答案，设定与正确答案语义互斥的目标答案；目标系统的检索器和生成器参数不可见。
3. 本地影子系统用于构造与筛选，包含影子分块器集合、代理检索编码器与影子生成模型。白盒梯度只来自代理端。
4. 目标端分块窗口与切分相位不由攻击者控制。图中要先出现完整投毒文档，再出现目标端分块产生的角色块。
5. 目标链路不配置额外交叉编码重排序器。主实验配置为 Top-5，形式化模型保留 Top-K。
6. 防御插在检索之后、生成之前；防御者在服务端能读取查询、候选块及相关表示与元数据，在线处理采用预先拟合、校准的固定策略。

### 1.2 攻击主图中的四个关键机制

- **互补角色**：规则／前提块 A 与实例绑定块 B 位于同一文档的远距位置。它们是语义角色，不是两个攻击者或两台机器。
- **等背景组合验证**：四种上下文都保留相同的 K−2 个干净背景块、固定槽位及总块数；以中性块替换缺席角色。筛选条件是 C00、C10、C01 不命中目标答案，C11 命中。
- **语义与检索解耦**：第一阶段通过后固定核心载荷及背景句；第二阶段只更新触发器。同一角色的前、后触发器为同一序列的两个副本。
- **实际文档重切分**：优化后组装完整源文档再切分，检查角色完整性、分离性与共同召回。有效影子视图上的检索损失不能被画成所有未知目标分块都必然成功。

### 1.3 防御主图中的四个关键机制

- **四维统计特征**：尾谱马氏距离、词项子空间残差、查询方向正交／平行分量比、首尾子窗余弦距离。线性逻辑回归融合得到连续风险分数。
- **查询级阈值校准**：Dfit 与 Dcal 独立，校准量是每个查询候选集合的最大风险分数，而不是把所有块混在一起求分位数。该校准针对统计告警，不代表整个复合防御拥有相同的整体误报保证。
- **跨块关系升级**：所有统计保留块进入实体—命题多重图；同源远距、低频桥接、命题冲突中的任一信号都会把该对的两个块送入待审集。仅有桥接关系不等于投毒。
- **单次按需复核**：Sjudge 非空才联合复核，判别 LLM 每次查询至多调用一次，回答生成 LLM 是另一调用。参照块来自当前未告警保留块，且其来源须不同于所有待审块；参照块可以为空。判为投毒的 U 被移除，其余块按原排名保留并截取至多 m 个。

## 4. 统一视觉规范

采用用户确认的蓝—橙—绿配色。

| 语义 | 色值 | 用法 |
|---|---|---|
| 正常 RAG、查询、共享服务 | 蓝色 `#0072B2` | 模块边框、正常数据通路、正常上下文 |
| 攻击载荷、可疑关系、攻击构造 | 橙色 `#E69F00` | 角色块、触发器和可疑关系；在防御图中不单凭橙色暗示已确认恶意 |
| 防御、净化、经复核保留 | 绿色 `#009E73` | 防御模块与处理路径；不表达绝对正确或保证安全 |
| 文字与中性辅助 | `#263238`、`#66717D`、`#CDD4DA` | 文字、辅助连线、边框 |
| 画布 | 白色 `#FFFFFF` | 至少70%画面为白色或近白色，极浅浅色仅用于很小的功能分组 |

采用二维、近矢量的学术插图风格；不使用立体透视、投影、发光、渐变、卡通黑客、装饰性大脑和商业看板。每张图最多两档字号。中文优先使用思源黑体／Noto Sans CJK SC 的清晰字形，所有文字水平排布。图片按约16.5–17.5 cm正文通栏宽度设计，避免缩小后正文标签低于约9 pt。

五张图沿用相同的长文档、文本块、候选列表、模型与存储图形。角色 A/B 同属橙色组，靠标签和小形状区别；普通数据、攻击、复核和证据支持同时用不同线型表达，保证灰度打印仍能分辨。

## 5. 直接使用方法

1. 打开对应编号的 Markdown 文件，将其中**唯一的完整提示词代码块**复制给图像生成模型。每个提示词都已自包含，无需拼接公共前缀，也无需上传整份报告。
2. 每次只生成一张；保持五张图采用同一生成模型和相同风格设置。建议先生成 02 的 RAG 架构图，确定图标与字形，再依次生成 03、04、01、05。
3. 每个代码块中的英文用于指导构图；双引号内的简体中文是需要实际呈现在图上的标签。数学符号、RAG、LLM、Top-K 等保留原样。
4. 提示词已要求直接输出一张图像。若工具支持指定尺寸，01／05 用3600×2700，02／03／04 用3600×2250；否则保持对应宽高比并选择最高可用分辨率。
5. 若第一张图符合预期，可将它作为后续图的**风格参考**，同时明确“只继承字体、颜色、线宽和图标，不继承布局与研究内容”。
6. 图题与正文图号由论文排版添加；提示词不把“图1”“图2”或完整长图题烧录到图片中，便于后续调整顺序。

## 6. 生图后的核对与修订

先核对科学含义，再调整外观。任何一项不满足都需要修改图片：

- 攻击箭头是否只落到一篇源文档，而不是检索器、LLM、系统提示词或两个独立块？
- 是否先摄入／分块，再索引／检索？是否凭空加入了重排序器？
- 双角色块是否来源相同、位置分开？两块共同出现是否只被标为所选构造的验证条件，而非普遍必然成功？
- 四组对照是否保持背景、总块数与角色槽位一致？
- 第二阶段是否只修改外围触发器，而不重新改写已固定的核心载荷？
- 低统计分数的块是否仍进入跨块检查？关系告警是否送审而非直接删除？
- 异源参照是否来自当前候选中的非待审保留块，且允许缺失？是否错误增加实时网络检索？
- 判别 LLM 是否为按查询至多一次，是否和最终回答生成区分？
- 输出净化上下文是否仅删除判定为投毒的块并保留原检索顺序，未凭空增加重写、重排、再检索或保证正确的结论？
- 原型图是否保留五个报告定义的模块，未虚构数据库产品、Web框架、云部署或已经上线的事实？
- 是否所有中文准确、无乱码、无跨线遮挡、无缩小后看不清的小字？

通用修订提示词：

```text
Revise only the following defects in the supplied figure: [逐条填写缺陷和正确关系]. Keep the established blue–orange–green palette, exact Simplified Chinese labels, aspect ratio and scientific content. Preserve all already-correct modules and connectors. Correct topology before adjusting spacing. Do not add new methods, numerical results, English explanatory text or decorative icons. Return one corrected figure only.
```

如果图像模型始终不能正确呈现中文，保留其图形构图，在后续排版软件中覆盖中文标签；不要把无法阅读的伪中文字作为论文成图。详细提示词约束了文字内容，但不能替代实际成图后的逐字核对。
