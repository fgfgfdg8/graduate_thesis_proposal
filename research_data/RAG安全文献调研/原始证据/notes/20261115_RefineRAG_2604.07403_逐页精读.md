## 3. 威胁模型、方法与控制权限

1. **攻击目标和已知信息**（p.4–5）：针对预先指定的问题 Q 和错误目标答案 Rt，使检索与生成最终输出 Rt。攻击者已知目标问题并自行设计目标答案；本实验由 DeepSeek-V3 产生错误答案后人工确认其与真值冲突（p.7–8）。不等于不知道问题的广谱攻击。
2. **控制权**（p.4）：推理阶段可向公开可索引语料注入少量投毒文本；作者以可编辑站点/论坛为动机举例，声称不改训练、参数或系统代码。受害者内部参数、梯度和具体配置不可见；允许本地使用 Contriever 代理及其他公开模型。论文没有证明真实维基或第三方站点被修改，伦理部分称公共数据上的隔离模拟（p.12）。不要把设想的公开站点写权限当成已完成的真实线上攻击。
3. **构造链**（p.5–7）：阶段 I 让生成 LLM 构造含 Rt 的候选，并把**单条候选 + 问题**送验证 LLM；能诱导目标答案的候选保留，再依与问题的检索相似度选择。阶段 II 冻结问题/目标答案关键词与停用词，对指定词性词逐词遮罩，由 MLM 给候选、代理检索器按相似度筛选并用 beam search 维持候选轨迹。阶段 I 的单条种子验证不证明经阶段 II 改写后的每条最终文本仍一定有效：正文算法未明确逐次/最终再次用生成器验证目标答案，生成保持缺少可核的完整检查协议。
4. **模型可见性与迁移边界**：主配置的代理和受害检索器均是 Contriever（p.8–10），因此这个主结果不是跨未知检索器的独立证据；Table 3 另测 Contriever-ms 与 ANCE 的代理迁移（p.10），并非对任意未知检索架构的保证。p.13 作者自己承认对稀疏检索器的效果仍需研究。

## 4. 真实语料、分块、预算和分母

- **数据背景，不自动等同已审计索引规模**：p.7 称 NQ 主要来自维基，约 260 万 documents；MSMARCO 来自 Bing 搜索结果，约 880 万 documents。每个数据集随机选 100 个闭式问题；目标错误答案使用 DeepSeek-V3 构造并人工验证（p.7–8）。文中未充分交代所用语料快照、实际索引条目数量、切块长度/重叠、源文档与索引块映射、摄取更新流程或可复现实验文件，故不能把背景规模直接当作本次已核实索引规模，更不能认定经过真实长文档分块。
- **注入预算**：对每一目标问题注入 **5 条投毒文本**；受害 Contriever 默认返回 **top-5**（p.8）。论文未说明这些文本在语料中是否总以同一源文档形式入库、能否控制真实 chunk 边界、5 条是否同时针对所有问题常驻、整个库实际投毒比例、原始源文档修改比例或总检索器调用次数。不能把“5 条/题”换算成全库固定污染率或单篇源文档的 5 个块。
- **构造参数**（p.8）：阶段 I 四轮，DeepSeek-V3 每轮生成 10 个候选、温度 1.0，最短长度写为 25（**原文未明示字符/词/token 单位**）；验证模型 Llama-7B；每轮选前 2 个继续生成变体。选前 5 个 seed 逐条进入阶段 II；10 次迭代、beam size 3、BERT-Large MLM 每次预测 20 个替换候选、spaCy 词性标注。原文没有给足每轮变体的生成次数及每次调用的确切账本；不能简单认定总 LLM 调用为 40 次。也未给出最终每条文本真实修改词数、编辑距离、总代理评分次数和美元/时间成本。单轮枚举候选数与最终替换词数不能互换。
- **ASR 的分母**：p.8 将 ASR 定义为模型回答中严格匹配预设错误目标答案的比例，L-ASR/V-ASR 分别是 Llama-2-7B/Vicuna-7B；p.7–8 给每数据集抽取 100 个问题。**论文没有在各结果格提供原始成功/失败计数、每题解码次数/随机种子、实际有效样本及其过滤策略；也未提供可核查的答案匹配归一化脚本。** 因此 NQ L-ASR 0.90 是作者报告的总体比例，不可未经记录将其说成已核实的“90/100 次独立攻击”。更不可与检索成功率混为一谈。
- **检索和隐蔽性指标的分母/实现**：p.8 仅说 Precision、Recall、F1 衡量投毒文本进入 top-k，并列出 GPT-2 PPL、自动语法错误 GE、查询词汇重合 ROUGE-L Recall、重复率 RR；未给可复核的完整逐 query 汇总、检索相关标签、去重/平均口径、语法工具版本、RR 算法及 PPL 分词/截断策略。表中 F1 不等 ASR，也不能把单条文本分数理解为检出率或某阈值下的防御逃逸率。

## 5. 结果、反例和文本内部冲突

- **主结果**（p.9 Table 1）：NQ 上 RefineRAG 检索 F1=0.89，L-ASR=0.90、V-ASR=0.85；MSMARCO 分别为 0.70、0.83、0.81。对比 PoisonedRAG (W)，检索 F1 分别为 0.95 和 0.95，**均高于** RefineRAG；MSMARCO 上 Prompt Injection 的 L-ASR=0.83、V-ASR=0.81，与 RefineRAG 均为**并列**。不能概括成所有指标均优于全部基线。
- **摘要及 p.9 的“最低重复率”与表 1 冲突**：RefineRAG 两集 RR 均为 **0.01**，PoisonedRAG (W) 均为 **0.00**。RefineRAG NQ 的 PPL=118.33，高于 PoisonedRAG (B) 的 55.11 和 Prompt Injection 的 107.01；MSMARCO PPL=127.53，高于 PoisonedRAG (B) 的 55.88。RefineRAG 在两集 GE 分别为 0.66 和 0.86，低于表内其他方法，但“语法分数更低”不等于真实事实无误或对防御可靠隐身。p.13 的“绕过流畅度过滤”没有对应过滤阈值、误报率和过滤后 ASR 实验，不能当实测绕过。
- **迁移**（p.9 Table 2、p.10 Table 3）：NQ 六个受害生成器 ASR 为 0.81–0.92；MSMARCO 为 0.73–0.83。检索器方面 NQ 的 Contriever-ms L/V-ASR=0.82/0.80、ANCE=0.70/0.68；MSMARCO 分别为 0.64/0.66、0.56/0.60。跨受害检索器发生性能下降，且仅覆盖所列配置。
- **两阶段消融不是跨块必要性消融**（p.10–11 Table 4）：NQ 中无阶段 I 的 L-ASR 0.72，无阶段 II 0.86，完整方法 0.90；这是构造算法两个阶段的消融，而非移除一个或多个注入文本块后检验目标答案。
- **参数叙述冲突与非单调性**：p.11 正文称 K=20 时 MSMARCO L-ASR 升至 **0.90**，但 p.13 Table 8 对应值为 **0.83**，0.90 是同一行 NQ L-ASR；保留冲突不自行纠正。p.12 Table 7 中 NQ 的 WLO=5 次 L/V-ASR 0.91/0.87，高于默认 10 次的 0.90/0.85。p.9–10 正文称 top-k 性能在 k=5 达峰；直接查看 Fig. 2，F1 曲线在 k=5 达峰，而 ASR 曲线视觉最高点略偏 k=6，图未给精确点值，不将该细微差解释为已核实数字。

## 6. 多块共同必要性与开题 A/B

**不能认定多块共同必要。** 本文是每题构造并注入 5 条单独优化文本（p.8）；阶段 I 单独验证候选与问题可触发目标答案（p.6），Fig. 1 示例的单条文本本身包含完整目标错误答案（p.5）。论文未报告逐一删除/保留注入文本的固定背景对照、每条召回位置、同一真实源文档的 chunk ID 与共召回，也没有检验“任一单块不足而组合充分”。5 条并发投毒、top-5 检索或阶段 I/II 消融均不能代替该证明；这不排除某些样本存在交互，只是现有报告没有识别出来。

- **A（攻击）**：开题当前正文 partitions/section3_content.tex 第 6、23–30、43、70–82 行把研究对象限定为仅改写一篇源文档，目标侧实际分块后两个同源角色块同题共召回；固定背景与槽位的 C00/C10/C01/C11 对照要求双块命中、单块和无块不命中。RefineRAG 是**预设目标答案、代理检索器指导、词级改写、向检索库投毒**的直接方法近邻，限制“首个词级检索优化/代理检索投毒”等宽泛表述；但其 5 条注入文本、单种子验证和报告的测试不建立单一真实长源、未知受害 chunker、实际同源块共召回或逐块共同必要。A 的受控组合对照也不能被误写成单独验证端到端因果的保证；与本文不同并不自动证明 A 完全没有其他先例。
- **B（防御）**：开题正文第 238、255–288、295–304、306–345 行为拟议的固定语义表征与四项统计、离线随机森林/正常查询阈值、跨块关系和异源参照复核；最终由复核判定后删块。RefineRAG 提供一个以语义自然和高相似度为目标的**攻方压力样本与局部词扰动对照**，但没有评估该防御、四项统计特征、查询级正常告警/最终误删率、跨块检查或正常多跳问答保留。它不能单凭 PPL/GE/RR 断言可绕过 B，也不能用作 B 已有效的证据。实际比较需在相同语料、切块、预算与独立干净查询口径下重新运行，并区分统计分支告警与最终 LLM 误删。
