## 方法及实验口径

1. **评估分解（pp.4、6–7）。** 对同一问题的等义改写，检索一致性用不同 Top-k 集合的 Jaccard 均值；生成一致性固定原查询的检索上下文；端到端一致性允许每条改写分别检索。输出一致性以词面 BLEU 和 LLM 裁判分别衡量。集合重合率、答案一致率和答案正确率不是同一指标。
2. **训练（pp.4–6、8）。** Con-RAG 的 PS-GRPO 对同一原始问题的多个改写分别采样输出，以其他改写输出的平均 BLEU 作为组相似奖励，再按单个改写内的输出标准化优势并更新生成器。短答案和多跳实验还加入基于真实答案 token F1 的准确率奖励；ELI5 长答案实验不使用准确率奖励，另加小 KL 项。训练是完整模型微调，不能概括为所有任务都无需答案监督或部署免训练。
3. **预算与设置（pp.6–8）。** 主设定使用 E5-base-v2、KILT Wikipedia、512-token 块、FAISS 和 Top-5；生成器为 LLaMA-3.1-8B 或 Qwen-2.5-3B。训练每问题 6 条改写、每条 4 次采样，奖励近似每个输出采样 3 条其他改写各 1 个输出；评价使用 5 条改写。短答案改写提示使用参考答案，长答案改写提示未给答案（p.13），因此不能把所有改写视为完全无监督或未使用标签。未在正文和附录中定位完整训练样本数、GPU 小时及显著性检验细节。
4. **裁判（pp.7、14）。** 对 LLaMA-3.1-8B 实验，一致性裁判为 LLaMA 3.3 70B；对 Qwen-2.5-3B 实验，使用 GPT-4o。一致性裁判和准确率裁判不是同一指标；跨模型裁判、自动改写及生成器均可能引入系统性偏差。

## 结果、反例与疑点

- Table 1：LLaMA-3.1-8B 的 MuSiQue 检索集合 Jaccard 为 36.6%，端到端信息一致性为 48.2%，固定上下文后的生成信息一致性为 69.7%；这说明不同层次均存在变化，不证明二者数值差就是单一因果效应。
- Table 2：LLaMA-3.1-8B、TriviaQA 下，RAG 与 Con-RAG 的 EM 分别为 56.0% 和 77.0%，端到端 LLM 裁判一致性分别为 77.8% 和 91.3%。该短答案实验的 Con-RAG 使用真实答案 F1 训练奖励；比较结果不能改写成无答案监督下的收益。
- 作者 pp.3、9 将多项结果概括为各数据集、各指标均最优，但反例存在：Table 2 的 2Wiki RM，CoT-RAG 为 41.0%，Con-RAG 为 40.0%；Table 9 的 Qwen 2Wiki，SFT 与 Con-RAG 的 F1 分别为 38.9%、38.4%，RM 分别为 38.0%、37.0%，端到端词面一致性分别为 70.9%、68.2%。这些差异限制“所有配置均最优”，不否定表中的其他收益。
- Table 4 的 ELI5/Qwen 奖励消融中，BLEU-1 的生成器 LLM 裁判一致性为 69.8%，BLEU-2 为 67.5%；BLEU-2 的端到端 LLM 裁判一致性与 LLM-Acc 分别为 42.0%、58.0%，高于 BLEU-1 的 38.2%、54.0%。不能将作者“BLEU-2 最好”概括成每一指标都最高。
- p.6 用 `sim(a,b)` 的对称性讨论减少重复比较，而 p.5 采用 BLEU，p.13 的 BLEU 定义区分候选和参考、含长度惩罚；普通 BLEU 不保证交换输入后数值相等。论文未说明此处是否采用显式对称化，不能仅凭公式认定实现错误，也不能无条件套用对称计算节省量。
- p.13 改写小节前言称使用参考答案确保可答，但所列长答案提示未包含答案；按具体提示分别描述。p.14 对不同生成模型采用不同一致性裁判；pp.7–9 训练奖励和正文主张的细节不能一概归并。

## 与开题的关系

该研究是**正常检索和生成一致性、改写稳健性、长/多跳 QA 效用**的参考，可提醒 A 在查询改写下分别报告证据集合和答案稳定性，也可为 B 增加过滤前后正常多跳问答及改写一致性比较。论文未构造攻击者控制的真实长源、未知分块后的同源互补块共同召回/逐块必要性，也未研究恶意检索块检测、过滤后的独立干净 query 最终 OR 误删率。其输出之间的组相似奖励不是跨检索块的投毒检测；高一致性也不能单独证明答案真实或安全。
