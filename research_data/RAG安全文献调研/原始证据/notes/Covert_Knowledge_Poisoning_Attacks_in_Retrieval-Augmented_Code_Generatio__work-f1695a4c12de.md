## 问题、威胁模型和载荷机制

论文针对检索增强代码生成（RACG），试图使生成代码同时满足用户功能意图并含攻击者预设的漏洞模式。p3 式 (1) 的优化项实际针对指定漏洞模式在输出中出现；作者称功能由构造设计间接保留，并未将功能正确显式写入该优化式。ASR 本身也不是功能正确或可实际利用的联合证明。

- **访问权限（p3、p6）**：攻击者无法直接查看目标知识库内的文本、获取 LLM 参数或确定实际检索器；能够以普通贡献者身份向可能被摄入的 GitHub、Stack Overflow 等公开源提交内容，并假设每个目标查询的 `N` 个污染样本实际进入知识库。场景 I 可获取或预测目标意图，p6 更具体地假设截获准确查询 `Q`；场景 II 只预设广泛编程主题，未预知测试的具体查询，生成主题相关变体。原文没有明确给出“造毒期间禁止查询受害接口”的限制，不能把该限制从其他论文移植过来。实验在污染材料进入评测库之后考察效果，不等于验证真实公共平台接受与生产摄入。
- **载荷单位与构造（p4 Fig. 1、p5–6 Algorithm 1）**：论文直接构造每查询 `N` 个独立的知识样本；每样本 `M=R⊕I`，`R` 是自然语言检索文本，`I` 由良性功能代码和诱导代码组成。场景 I 使用 `R=Q`；场景 II 基于主题生成语义变体。作者对目标漏洞代码生成不同的删词元变体，要求分别通过 Bandit、Semgrep、Snyk Code，选择词元并集覆盖原目标的互补变体，再与良性代码拼装。p5 算法写随机选择被删除的词元子集，p6 叙述又描述从单词元向多词元渐进尝试；两处粒度记录在此，不把算法实现次序视为已唯一确定。
- **机制及证明边界（p4、p11、p15）**：作者以片段互补、语义关联、跨上下文融合和代码补全解释漏洞重构；图示是机制示意，不是对模型内部注意力因果机制的单独测量。单样本通过静态扫描不等于独立证明可编译、可运行或安全；通过哪些工具是作者的方法描述，不是本次复现结论。p15 的单污染样本位置实验仍有非零 ASR，因此不能把本文整体效果说成严格要求固定两块同时出现。

## 评测口径：检索、生成及实际分母

p6–8：CoNaLa 含 2,879 对意图与代码，作者随机选 100 个自然语言目标查询；考察四种检索器、八种生成模型，默认 BGE、Qwen2.5-7B、CWE-367、每目标查询 `N=5`、Top-`k=5`。其攻击条目是独立样本而非由一篇长源经未知目标分块器产生的同源角色块。

- **检索指标（p7）**：Precision 是 Top-k 中污染样本数 / k；Recall 是被检索到的污染样本数 / 对该目标查询注入的 N；F1 为两者调和平均。其论文定义是样本级覆盖/占比，不能改称“两指定互补块同时召回的查询比例”。公开脚本另以累加 TP/FP/FN 计算全体的汇总值，宏/微平均与论文每查询定义是否对齐有待核验。
- **生成 ASR（p3 式 1、p7、p14–15）**：目标函数在 `K` 个目标查询上平均目标漏洞模式出现的指示量；这里大写 `K` 是查询数，与小写检索深度 `k` 不同。p7 将 ASR 描述为生成内容中包含指定漏洞代码的比例，p14 将其称为 string-based。文章选了 100 个目标查询，但未逐表明确给出最终有效输出数、零召回/失败记录的处理或分母；不能因采样规模就把每个表值断言为严格 `x/100`。论文 ASR 的指标文字没有像 CodePoisonRAG 那样显式要求“对应污染条目召回且输出漏洞”这个联合事件。
- **公开脚本的分母歧义**：当前 [run.py](https://raw.githubusercontent.com/Coderrag/Arachne/main/run.py) 的可见路径先逐查询检索，仅当 `poison_num > 0` 才生成并记录输出；[evaluate_cases.py](https://raw.githubusercontent.com/Coderrag/Arachne/main/evaluate_cases.py) 的示例计算为命中数除以读取记录数。若该路径直接串联，分母是有污染召回并形成记录的查询，可能产生条件比例，而非全部 100 查询。代码是否为论文各表使用的完整版本及该路径是否实际生成那些表均未验证，不能直接断言论文所有 ASR 的实际分母就是条件分母。此观察与论文按查询求平均的形式化一起保留，等待原始运行记录澄清。
- **功能与安全（p7、p11 Table V）**：EM 以生成代码是否逐字符匹配标准答案为判据，Pass@1 使用隔离危险系统调用的 mock 环境执行单测。MaxKB、CWE-367、场景 I 的表中 ASR 为 `0.87`、EM 为 `0.70`：这是两个边际比例，文章没有给出同时命中漏洞且功能正确的交集计数或共同分母，不可拼接为 87% 功能正确的攻击成功，也不可由此推断实际可利用率。实际生产采纳与利用未验证。

## 结果、对照与原文冲突

- p8 Table I 在 Qwen2.5+BGE 下，CWE-78 场景 I/II 为 `0.65/0.71`，CWE-295 为 `0.78/0.89`，CWE-367 为 `1.00/0.89`，CWE-614 为 `0.66/0.68`。p9 Table III 文本称为默认设置，但其 Arachne 的 CWE-78 写 `0.71/0.65`、CWE-295 写 `0.89/0.78`；p12 Table VI 无防御列与 Table I 一致。如果三表为同一默认条件，前两类的场景 I/II 存在未解释的互换；不静默选择或据此估计单次试验成功数。
- p11 Table IV：互补、非互补、仅关键词三种设计，跨四个 CWE 与两场景的作者报告平均 ASR 分别为 `0.77/0.33/0.21`。非互补对照还改变句法或语义连贯性，关键词对照还去除结构与逻辑关系；这支持所评估设计之间的差异，但不能单独证明特定注意力机制或在固定背景下每块不可缺少。
- p9 Fig. 2–3 及 p11：改变检索深度 k 或每查询投毒量 N 时，作者报告浓度和召回的权衡；这些是该配置下的结果，不能延伸成未知分块器或任意真实摄入策略的稳健性保证。p15 Table XI 固定单污染样本位置为 Top-5 第 1、3、5 位，ASR 均非零。
- p12–13：PPL 区分实验抽取 2,000 条干净与 2,000 条污染样本，场景 I/II 的 AUC 为 `0.66/0.68`。p12 文字把两个分布重叠比都标为 Scenario I，p13 Fig. 4 标成 I `0.72`、II `0.68`，保留这一文字/图示冲突。p13 人评为 5 人、每人 10 毒 + 90 良性，是否重用同一批样本未交代，不能当成 500 个相互独立样本。
- p14 Table VIII：CodeGuarder 安全知识增强下，作者报跨四个 CWE 及两场景平均 ASR 从 `0.78` 降至 `0.38`；该防御不是开题 B 的检索前馈过滤器。p14 Table IX：从生成结果抽取 200 段与 CodeQL 对照，报告平均一致率 `0.95`。一致率不等于准确率、人工真值或实际可利用性；各 CWE 的样本分配不明，不换算精确一致条数。

**A 的直接重叠与区别**：跨检索条目的互补碎片、联合上下文与诱导生成已是明确先例，不能泛称首次组合/互补投毒；本文的独立注入条目与代码漏洞任务不同于开题的单源、未知受害分块、双同源角色完整性及固定背景缺一对照。本文未报告相同的未知分块器变化和双角色必要性实验，因此不能直接当作这组受限条件已被验证，也不能证明其他论文不存在该交集。

**B 的直接重叠与区别**：本文 p15 已讨论跨块聚合语义检查和来源审计，不能把这些方向本身作为首创；它并未实证开题拟采用的四统计、语义融合、跨块关系及异源复核，也没有据此证明该防御有效或成本可接受。Arachne 的 PPL 分类、CodeGuarder 降幅及人工误报均有各自实验分母，不可替代开题的干净查询级统计告警率、最终误删率和良性多跳保留。
