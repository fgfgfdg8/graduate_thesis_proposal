## 3. 研究问题、攻击者能力与具体算法

论文旨在提高某个投毒文档的召回并诱使生成器输出攻击者指定答案。它的“joint”是**检索器与生成器两个模型的优化目标联合**，不是两个同源文本块的联合召回，也不是验证互补前提缺一不可（pp.1–3）。

| 维度 | 作者设定 | 与开题比较时必须保留的边界 |
|---|---|---|
| 访问能力 | 白盒获取检索器和生成器的结构、参数及输入梯度；对语料有有限写入权限，通常每个目标查询插入一份毒文档，不能修改或删除已有合法文档（pp.2–3） | 开题 A 是改写同一真实源文档；白盒设置不能直接等同未知目标管线。每查询一篇也不代表全评测仅一篇 |
| 可见性 | AWF 常规设置使用目标查询对应的 Top-k 文档及相似度；另以合成语料近似（pp.2、4、7、13） | 已有可观测 Top-k 的结果不能直接推广至不可查询、未知 chunker 的目标 |
| 载荷与检索单位 | 在已有毒文档模板内加入可优化序列，按单个文档被检索和目标答案出现来衡量（pp.3–5、14） | GTA 处理的是**两个模型 tokenizer 的 token/字符偏移对齐**，不是摄入流水线的文档分块对齐 |
| 防御 | 实测输入扰动和针对困惑度的约束，其他检索感知、来源治理为讨论（pp.15–17） | 不能把讨论中的设想写成已实现或已证明有效的防御 |

**联合目标（p.3 式1–4）**：检索损失提高查询与毒文档的相似度；生成损失度量给定查询及检索上下文时输出目标答案的负对数概率。式2在毒文档进入 Top-k 时才纳入生成损失，AWF 自适应调整两者权重。Top-k 和指标函数是离散选择；把这一优化框架称为目标或算法，不等于已经证明检索—生成全链路可微或全局最优。

**三个组件（pp.3–5、10–12）**：CVP 利用共同 token 的嵌入训练编码—解码映射，再用最小二乘形成跨词表的梯度投影；GTA 借两个 tokenizer 的字符偏移把检索侧梯度对齐到生成侧；AWF 以毒文档与最高分干净文档的相似度差、Top-k 相邻分差的平均值构造排序稳定性指标，并动态调整权重。然后进行候选替换、前向重评及贪心更新。上述是论文描述和局部代码观察，不是对全部运行路径的复现。

**边界条件（p.4 式6–8）**：AWF 分母是 Top-k 相邻分差的平均值；分母为 0 或没有足够分数间隔时，式子本身不能给出该比值。作者公开仓库主分支页面当时显示 commit `8707acb23954d9683483b9dc2406684c301a39d2`；固定版 [utils.py 第20–42行](https://github.com/NicerWang/Joint-GCG/blob/8707acb23954d9683483b9dc2406684c301a39d2/utils.py#L20-L42)中的 `adaptive_ratio` 对 `diff_cnt` 和平均分差直接除法，未见该函数内部的零值保护。这只是静态边界观察，不证明论文实验发生异常，调用方限制和实际输入仍未核。

## 4. 评测口径和实际结果

- **样本与配置**：MS MARCO、NQ、HotpotQA；与 PoisonedRAG/LIAR 的定向比较沿用 PoisonedRAG 的每数据集 100 个查询；Phantom 批量对照为每个触发词 25 个查询。Contriever-MSMARCO / BGE-base-en-v1.5 检索，Llama3-8B / Qwen2-7B 生成，Top-5；常规定向实验重复三次、贪心解码，批量实验附录明确只进行一轮（pp.5、13–14）。同一批次的 100 条不是新增于前作的独立样本，三次运行也不自动等于三个独立查询样本。
- **指标**：`ASRret` 是目标查询的毒文档 Top-k 检索命中比例；`ASRgen` 是答案包含攻击者目标字符串的比例；`Posp` 是毒文档的平均排名。表1括号内 `ASRgen` 只针对未优化初始攻击失败的子集，分母与表中总体不同（pp.5–6）。后者不是仅在已召回条件下计算的 ASR，目标字符串命中也不自动证明完整回答语义被成功操纵。
- **主表例子（p.6 Table 1）**：NQ / Contriever / Llama3 下，Joint-GCG 的 `ASRret` / `ASRgen` 为 99.0% / 92.0%，GCG 为 72.0% / 72.0%，LIAR 为 93.33% / 89.0%。HotpotQA / Contriever 下，Joint-GCG 的 Llama3 `ASRgen` 为 97.3%，Qwen2 为 99.0%；Qwen2 括号内 95.8% 是未优化失败子集，不能与总体列混用。结果没有自动控制所有预算差异，见下节。
- **消融（p.6 Table 2）**：NQ / Contriever / Llama3，完整方法 92.0%，同时去 CVP 与 GTA 91.0%，去检索损失 86.67%，GCG 72.0%。作者正文说同时去 CVP 和 GTA “consistent 2% average decrease”；按表2六个配置逐格等权相减，差为 0.67、0.33、1、2、2.33、0 个百分点，均值 **1.055 个百分点**，且 HotpotQA/Qwen2 为 0。可能存在不同平均口径或四舍五入，本次不代作者裁定，但不能把该 2% 当作六格等权均值或逐格严格下降。
- **缺失真实 Top-k 的代价（p.7 Table 3）**：MS MARCO / Contriever / Llama3 的 `ASRgen` 从真实 Top-k 条件下 94.0% 降为合成语料计算 AWF 下 62.0%；Qwen2 为 96.33% 降至 58.0%。BGE / Llama3 为 87.0% 降至 41.0%。合成条件仍有攻击效果，但不是“移除真实候选访问后效果近乎不变”。p.13 写每查询生成 10 篇合成文档，所附提示词却要求 11 篇；最终实际数量待作者数据核验。
- **迁移与图文冲突（p.7 Figure 6）**：图的横轴为 **Surrogate Model**、纵轴为 **Victim Model**。按图中 Joint-GCG 矩阵读取：Contriever 代理 → BGE 目标 `ASRret` 为 96%，BGE 代理 → Contriever 目标为 87%；正文文字恰好将两个方向反写。此处只报告图文不一致，未取得原始结果判定哪一处正确；两项是检索命中，不是目标答案成功率。Figure 7 的 GPT-4o 受害模型栏为 22%（未优化 20%），作者所称 2% 改善是在该设置中的 **2 个百分点**，不是所有黑盒模型的泛化保证。
- **批量攻击（pp.14–16 Table 7）**：单份毒文用于多个带同一触发词的查询；25 查询/触发词、一次运行，目标是拒绝服务。作者报告 `xbox` 触发下第4步 Joint-GCG 为 92%，Phantom 为 80%；这不等于两块互补，也不证明对未见查询泛化。

## 5. 防御结果、成本及尚未解决的原文差异

1. **输入扰动的安全—效用权衡（p.16 Table 8）**：MS MARCO / Contriever / Llama3，SmoothLLM 使攻击 `ASRgen` 从 94% 降至 53%，无攻击正确回答率从 77% 降至 72%；Qwen2 分别从 96% 降至 56%、71% 降至 66%。这是作者特定输入扰动设置，不是 B 的检测率、查询级误删率或多跳证据保留率。
2. **针对 PPL 的适应性攻击（pp.15–16 Table 9）**：作者声称只接受困惑度低于良性语料第95百分位阈值的候选；MS MARCO / Contriever / Qwen2，32步时表9报告 `ASRret` 100%、`ASRgen` 73.33%，未优化 49%。同页正文却称未优化为 54%，与表不一致；不自行选择覆盖。作者没有由此证明任意语义、来源或跨块检测器均可绕过，也未在该表给出真实部署的查询级误删率。
3. **128步 LIAR 的反例（pp.14–16 Table 6）**：正文声称 Joint-GCG 在全部配置的 `ASRgen` 均优于 LIAR 128步，但 NQ / Contriever / Llama3 一列为 Joint-GCG **92%**、LIAR **94%**；MS MARCO / Qwen2 两者均为 96%。同页表格直接反驳严格“全部更高”；不能单靠此表判断公平总计算量。
4. **优化预算表述待解释（pp.5、14–15）**：正文及附录在强调公平条件和 64 步的同时，把 LIAR 描述为检索/生成各 8 步；附录另报 LIAR 128 步。8+8 与表头 64 的对应关系及每轮到底何种单位未说明；须拿作者脚本、日志和前向/反向调用预算核验，不推断实际执行有误。
5. **成本不等于每查询总成本（p.17）**：作者称特定检索器—生成器对的 CVP 预处理在单张 A6000 上约2小时，可复用；未给出足以比较所有方法的完整端到端延迟、GPU成本和开销分解。pp.13–14 的合成数据和候选替换不等同真实文档摄入。作者公开 [README 固定版](https://github.com/NicerWang/Joint-GCG/blob/8707acb23954d9683483b9dc2406684c301a39d2/README.md)列实验脚本及结果 notebook；本次没有运行它们，也未核全部日志、数据或权重。
6. **80/20 的对象（p.11 附录 B.1）**：划分对象是检索器与生成器共享的 **token 嵌入对**，用于训练和验证 CVP 映射，不是把每数据集 100 个攻击查询划成训练／验证集。HotpotQA 的总体值与未优化失败子集值必须按 Table 1 分别转述；[总结报告](<../../../../docs/RAG安全文献攻防技术手段总结报告.md>)已按此口径说明。

## 6. 与开题 A/B 的撞车边界和后续检验

**A：直接撞车及剩余可检验交集。** 不能把“同时考虑投毒文本被检索和目标答案被生成”“联合检索与生成优化”“用梯度改进载荷”单独作为开题首创：Joint-GCG 已明确提出这些宽层次内容。其 CVP/GTA/AWF 解决模型词表与梯度融合、排名稳定性，不是从一份真实长文档经过未知受害 chunker 得到两个不同同源角色块。论文没有报告两块载荷的完整性、真实共同召回、固定背景四组 `C00/C10/C01/C11` 中每块的共同必要性，也没有仅修改一份既有真实来源文档的实验。开题中这些条件的组合仍须被真正实现并用目标侧采集的分块与排序验证；差异不是自动的新颖性或效果保证。参照[开题研究内容](<../../../../partitions/section3_content.tex>)第43–77、82行及第125–180行。

**B：威胁测试近邻，非同类防御。** Joint-GCG 使用查询—文档相似度、排名与生成反馈构造攻击，其 PPL 自适应实验说明仅看单一流畅度信号的防御有局限；它没有提出对 Top-k 逐块留一生成反事实、来源/偏移溯源、异源参照核验或正常多跳桥接块保留的防御。RAGuard 的 ZKIP 已是检索后生成留一的直接前例，Edemacu 等的 FilterRAG/ML-FilterRAG 已覆盖逐候选生成与轻量监督统计过滤；不能把这些宽机制作为 B 的独创。建议在相同 Top-k、相同可观测性和按查询划分的数据上，以 Joint-GCG 及其 PPL 适应性变体、RAGuard ZKIP 和 B 分别比较目标答案成功率、毒块召回/过滤、干净查询误删、正常多跳支持块保留及生成调用/延迟；该评测目前尚未实施。B 对同源块和异源参照的设计不能仅靠本篇攻击实验获得有效性证明。
