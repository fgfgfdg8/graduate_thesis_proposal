## 一、问题、边界与攻击者权限

论文研究：在代码生成 RAG 中，通过嵌入表示的相似度操控，让攻击者选定的危险代码进入检索上下文，进而观察生成代码是否包含目标危险构件。查询或代码的不可见 Unicode 扰动主要改变检索阶段，恶意代码被采用发生在生成阶段（第 1–5 页）。**输出中存在危险代码、静态工具报出漏洞，并不等于代码已经部署或执行，也不证明已造成真实环境入侵。**

| 场景 | 需要控制的对象 | 额外条件与不能省略的权限 |
|---|---|---|
| Q2T，扰动查询 | 可改写送入检索器的用户查询；目标代码可作为待检索候选 | 要能调用所针对的嵌入/相似度接口评估候选扰动；还需目标代码已进入候选库。示意入口包括查询增强工具或不可信 skill。 |
| T2Q，扰动目标 | 可将所选危险代码及扰动写入或送入目标检索语料 | 要能围绕目标查询使用嵌入/相似度评分接口构造扰动；插入后仍须被摄入及进入候选库。 |
| Both，双侧扰动 | 同时控制查询与语料中的目标代码 | 两侧权限同时成立；论文第 4 页的双侧构造与另两种差分进化优化并不完全相同。 |

黑盒是指无须模型权重、梯度或 tokenizer 内部信息，**不是零权限、零查询或无需相似度反馈**。第 3–4 页假定可多次调用嵌入及相似度评分；第 10 页概括的语料写入权限是语料侧要求，对查询侧还应单独说明。仅凭论文不能认定攻击者能实际修改某一产品的用户查询、控制目标语料，或能用本方法影响不可访问的检索接口。

Q2T/T2Q 用差分进化搜索字符位置与种类；Q2T 的目标同时考虑远离参考良性内容、靠近目标，T2Q 优化目标与查询的相似度（第 3–4 页）。所用 382 个字符属于 Mn/Cf 类。三种数据集并非对应三个相互独立的真实部署；固定目标和检索库构建方法会影响排序，不能将文字不可见等同于任何审计界面都不可见。

## 二、实验设置与分母

1. **源样本及候选集。** Java VFD 239 个、Python Alpaca 256 个、CyberNative 424 个；合计 919 是三个源集合大小的简单相加，不是所有模型、目标、预算和重复运行后的实验次数（第 4 页）。Java 和 CyberNative 提供安全/不安全代码对，Java 查询由 DeepSeek-R1 合成；Alpaca 为一般代码指令与参考解答，目标为每轮选定的固定片段。附录示例是按长度与 ASCII 条件挑出的示例，不能证明全体样本的质量和标签正确（第 35–40 页）。
2. **模型、目标与预算。** 论文列 14 个检索嵌入模型、3 个数据集，按场景及预算只做部分模型/目标组合；不是每个单元都执行完整笛卡尔积（第 4–7 页）。CyberNative 测试 10%、20%、30% 字符扰动预算，Java/Python Alpaca 测试 50%；第 19 页 A.2 的 combined best 合并多个预算的最佳结果，不能当成某一个固定预算的结果。第 4 页报告种群 32、最多 3 次迭代，第 10 页又称 1 generation；第 5 页随机基线报告 64 个候选。初始化是否计入迭代及各实验实际调用次数未能由论文消歧，不能擅自声称预算完全一致。论文还报告总体约 480 GPU-days 和 440 亿 API tokens，是作者报告的累计成本而非本次复现测量。
3. **检索分母。** 表 3 的 Top-k 为目标出现在相应 Top-k 的案例比例（第 5–6 页）。例：SFR-2B、Alpaca A1、Q2T、Top-1 为 3.91%；给定该数据集 256 条，数值与 10/256 一致。相同条件 Java B1 为 99.58%；不同目标或嵌入器不能相互替代。14 模型上分别评测，不足以证明同一未经重新优化的扰动跨模型迁移：第 10 页明确说按检索器优化且跨检索器迁移未测，与第 10 页通用子集可迁移的表述之间需要实际迁移实验区分。
4. **生成分母。** 第 5 页写仅对目标成功进入 Top-k 且代码符合语法条件的案例做生成评估；第 8 页明确图 5 是 retrieval-success-only，附录 A.2（第 21 页）也明确只对成功检索的查询分析生成代码，并针对相同查询比较基线。第 25 页使用正则抽代码，并在生成不可编译时最多再试 3 次、改变随机种子与采样。论文没有为各表单元完整列出实际检索成功数、有效代码数、各次重试与最终有效样本数。不能将图 5 的条件比例直接称为全样本端到端 ASR，也不能把静态告警数当成独立样本数。
5. **表 4 两面板不可不加说明地合并。** SFR-2B 上半面板中，Alpaca A1/Q2T/Top-1 为 3.52%（第 7 页），图 5 对应生成条件比例约 90%，表 3 检索比例 3.91%；`3.91% × 90% ≈ 3.52%`，与全体样本上的联合比例相容，但这只是算术一致性，**不能单独证明每个单元的分母或实现**。下半面板 oai-ada + qwen3-coder 的同数据、目标与 Top-1 为 100%，而表 3 对应检索率为 38.28%；在同一原始样本和事件口径下联合成功不可能高于检索率。因此下半面板至少不能直接当作与该 38.28% 同分母的全样本联合成功率。两个面板的精确计算以及可编译筛选如何计入，应通过版本匹配的逐条结果/脚本或作者澄清，不应猜填。
6. **其他内部不一致。** 第 8 页正文称 Java VFD/Q2T 的 k=1、3 分别为 62.76%、3.35%，但第 7 页表 4 对应数为 53.8%、0.8%，第 8 页图 5 显示约 54%、1%；正文数值与表、图不一致。第 9 页写漏洞计数 279、71、34 并配以 2.82×、7.21×；直接数量之比分别约 3.93×、8.21×，而 `(279−34)/34≈7.21` 表示相对增量，不应把这两个标注照搬为数量倍数。第 8–9 页由单侧成功集合包含关系推断跨模型 Both 与 Q2T 相等，但该包含关系本身不能证明两侧联合扰动无额外效果；表 3 的 SFR-2B 双侧结果也应单独看待。

**可复用的汇报口径。** 对同一预先登记的查询集合，逐条记录 `N`（全部查询）、`H`（目标被检索到）、`V`（最终输出可提取且通过语法/编译检查）、`M`（输出含目标构件），分别报 `H/N`、`(H∩V)/H`、`(H∩V∩M)/(H∩V)` 与 `(H∩V∩M)/N`，并披露未执行生成、缺失、重试和失败。若只对 H 生成，应保留 H 以外未生成的状态，说明按预设事件如何计算全样本联合成功，不能把未观测生成误称为已生成的失败。静态告警另报“告警数”和“至少一个告警的样本数”。

## 三、生成提示词、检测与防御

- 第 26–27 页的 Java VFD/Python Alpaca RAG 提示词明确要求信任并合并**所有**检索到的片段；CyberNative 的第 27–28 页提示词允许选择片段。这是关键实验条件：前两数据集的生成器被系统提示要求采纳所有检索代码，不应将所得目标复现率直接外推到能够拒绝或甄别不可信上下文的普通代码助手。
- 目标构件由规则匹配及 Bandit/FindSecBugs 两种视角检测（第 5、21–25 页）。附录承认 Java 某目标即使逐字复现也未被 FindSecBugs 报出；Bandit 对部分严重构件只给 LOW，且可能为同一问题产生重复告警。因此需检查误报、漏报与人工语义有效性；危险 API 出现不自动等同实际可利用。
- 第 9、29 页表 5/B.1：jina-base、Java VFD、Q2T 下 Top-1 为 50.2%，NFKC 后仍为 50.2%，按 Mn/Cf 类过滤后为 0%。这是特定模型、数据和攻击下的结果。表 B.1 中 oai-ada/CyberNative 的类别过滤后 Top-1 仍为 16.9%、Top-5 为 22.7%；残余召回可能源于原始语义对齐，不等于过滤失效，也不支持“危险目标永不被召回”。
- 382 个所选字符在论文评测中不被四种标准 Unicode 规范化消除；不能据此断言所有 Unicode 攻击都可通过 Mn/Cf 消除。第 30 页自己列举组合音标、复杂文字和 emoji 等的合法用途，第 11 页承认没有量化真实合法查询的效用损失。只过滤索引表示并保留原文也仍可能改变多语言检索，且保留原文不自动消除语义危险代码。非自适应防御、未评测 BM25/交叉编码器重排及尚未量化合法多语言效用，限制部署结论（第 10–11、28–31 页）。

## 四、与当前开题的 A/B 对照建议

只读依据：[研究内容](../../../../partitions/section3_content.tex)第 6、30–31、221–238、304–305、327–345 行；[研究难点](../../../../partitions/section7_difficulties.tex)第 3–19 行。

- **攻击问题不同。** 开题 A：攻击者仅篡改一篇源文档，以影子分块器与代理模型构造规则/实例两个互补载荷，要求分块完整与两块共同召回；不取得目标系统检索得分。RAG-Pull 的文献 B：重点操纵单个危险代码目标的召回及其后续复现；Q2T 还修改查询，论文优化假设可访问相似度反馈。两者的载荷语义、权限、评价任务和成功事件均不同，不能仅按论文原表横向排优劣。
- **权限匹配的攻击 A/B。** 在相同数据、查询、目标、分块、检索器、Top-k、生成器、候选数量及可计量的模型调用预算下，分别记录可编辑源文档数、能否改查询、对目标系统是否有相似度反馈。以单文档 T2Q 的受控实现作为可比扩展：一组只用影子系统评分以匹配开题权限；另一组开放论文式嵌入/相似度查询，用于估算更强权限带来的变化。Q2T 和 Both 作为额外威胁模型分层报告，不并入开题既有单文档权限。保留文档不可行、分块失败和检索失败样本。
- **防御 A/B。** 在相同攻击输入、目标集合和检索配置下，比较无防御、NFKC、Mn/Cf 类别过滤、开题检索后统计/语义评分加跨块关系与 LLM 复核，必要时再比较过滤+开题方案。类别过滤位于检索前，而开题防御位于检索后、生成前：应重跑受过滤影响的索引/查询并计入预处理与重检索成本，不能把同一份检索输出上的事后删除冒充检索前过滤。Q2T 可能在现有防线之前改变召回，不能预设已被覆盖。
- **结果与效用。** 分别按上文 N/H/V/M 口径报告检索、条件生成与全样本联合成功；开题另计两个角色块同时召回、双块合取诱导成功和各单块对照。对干净查询报告问答/代码任务质量、正常多跳证据保留、误删和复核调用量；对多语言文本与合法代码字符单列效用及延迟。固定生成提示与解码重试规则，并对强制合并所有片段的提示做消融。
