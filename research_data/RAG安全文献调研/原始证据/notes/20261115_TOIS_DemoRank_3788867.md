## 二、研究对象、方法和威胁边界

**问题。** 给定查询及其某个候选段落，先从有二元相关性标签的历史 `(query, passage, Yes/No)` 示例池中选择 few-shot 演示，再让 LLM 对当前查询—段落是否相关作 pointwise 判断，按归一化的 Yes 概率排序段落（物理 p.7–9）。该 Yes 是检索相关性标签，不是段落事实为真、来源可信、无恶意或最终问答正确的认证；FEVER 和 HotpotQA 的名称不能把这个实验自动变成实际事实核验或多跳证据保留实验。

**DRetriever。** 从训练集配平正负相关性示例。对一个具有已知标签的训练输入，用冻结 LLM 衡量各单示例令模型给出正确标签的概率，以此产生候选次序和训练监督；共享参数双塔检索器结合对比损失及排序损失学习候选召回（p.9–10）。因此 LLM 打分要用已知训练标签；不应表述成测试时无需标签即可直接获得相同的正确答案概率监督。

**DReranker。** 用已训练 DRetriever 先取候选，LLM 对“已有前缀 + 一个候选”的组合打分，按排名概率逐步采样训练前缀；同一前缀、仅最后一个示例不同的序列构成 pair，交叉编码器通过 list-pairwise 损失学习条件排序（p.10–12，算法1）。贪心/采样构造近似而非证明找到全局最优。文中依赖侧重示例的顺序、多样性及组合对标签预测的影响（p.4、7）；它不是已经证明两个事实片段共同必要的因果关系，也不是图结构溯源或来源独立性。

**推理说法未完全一致。** p.9 图2和 p.11 文字描述 DReranker 顺序选取；p.12 §4.4 字面上却说每一步取组合 LLM score 最大的示例。两处未解释两种说法如何对应。公开版本代码与论文的另一个具体差异见第六节；现有材料不足以确定论文表格实际跑的是哪一路实现，不能自行消解。

**威胁模型。** 这是一篇排序/示例选择研究，并未构造针对 RAG 的攻击者、单源篡改能力或投毒训练/测试集；不存在论文所报告的攻击成功率、投毒检测率、干净查询误删率或跨来源事实核验保证。这个结论限定已阅读的本期刊版本，不外推所有相关工作。

## 三、实验设置及分母

- 论文 p.12–14 报告的数据集规模：HotpotQA 7,405 个问题，NQ 3,452 个问题，FEVER 6,666 个 claim，MS MARCO dev 6,980 个 query，TREC DL19 43、DL20 54 个 query。前 3 个各自训练和测试，后 3 个共享 MS MARCO 训练数据。以上是**论文对各集合的表述**；尚未获得各表的逐 query 结果及过滤清单，不能证明每个表的有效分母必然等于上述规模，也不能把不同数据集或重复实验相加当独立样本总数。
- 另评测 7 个 BEIR 数据集：Robust04、SCIDOCS、DBPedia、NEWS、FiQA、Quora、NFCorpus；采用 MS MARCO 演示池做跨数据集测试（p.18–20）。具体每集合的有效 query 分母在本次阅读中未核实，不猜测。
- p.13：默认 LLM scorer 与 passage ranker 为 FLAN-T5-XL；DRetriever 用 e5-base-v2 初始化，DReranker 用 DeBERTa-v3-base 初始化；训练候选 N=50、M=50，构造训练序列最大 K=3；两者均训练 2 epochs。论文主实验推理候选 D=30；初始待排序 passage 为 BM25 top-100（p.14）。这里 D 是**演示候选数**，不是 RAG 检索块数量，也不是被篡改文档数。
- 主度量为 NDCG@5、NDCG@10，反映给定相关性标注下的排序质量；不是 QA 准确率、恶意内容检出率、攻击成功率或可信证据校验率。表4称 paired t-test 加 Bonferroni；其他表显著性口径按各自表注，未获取逐 query 原始结果复算。

## 四、重要结果与限制（物理页码）

1. **主表，p.15 表4。** 3-shot HotpotQA NDCG@10：DemoRank 67.03、LLM-R 64.54、0-shot 60.65；FEVER 对应 48.43、45.85、38.92。需要同时看 Initial Order：FEVER 的 BM25 初始顺序是 **65.13**，高于 DemoRank 的 48.43；其 NDCG@5 分别为 62.94 和 46.08。故不能据论文对部分演示选择方法的提升，概括成“所有数据集均优于初始检索顺序”。表中 DemoRank 数值被加粗，不能据粗体忽略 Initial Order 的更高数值；没有进一步核实该列是否有未说明的特殊统计处理。
2. **消融，p.16 表5。** FEVER NDCG@10：完整方法 48.43，去掉 DReranker 44.40，忽略依赖的变体 46.64。此对照支持论文条件化示例选择在该设置中的效用；不能证明两段材料互为因果必要条件或抵御协同投毒。
3. **监督排序比较，p.17 表6。** 以 MS MARCO 测试列为例，500K 训练 query 时 DemoRank 35.31、monoT5 40.05；20K 时 DemoRank 34.97、monoFLAN-T5 32.90。高资源环境不是全面占优；数据量和模型设定需按表对应。
4. **示例数与候选数，p.18–19 图3、图4。** FEVER 和 HotpotQA 从 3-shot 到 4-shot 均下降。§5.6 先称增加 D 一贯改善，随后又明确承认 D=40→50 下降；图4横轴含 50 而图题只列 10、20、30、40。结论仅支持文中测试范围内存在数量—效用权衡。
5. **跨域和模型，p.19–21 表7、8。** 表7使用 MS MARCO 训练出的演示选择器在七个 BEIR 数据集上测试，不能等于所有领域泛化。表8 Mistral 的 DL19：DemoRank 64.85、EPR 66.98；DL20：DemoRank 58.29、BM25 61.00。因此平均指标提升不等于每个数据集和模型都最优。
6. **延迟，p.20–21 表9。** FLAN-T5-XXL，3-shot FEVER 为 18.69→20.64 秒/查询、HotpotQA 为 23.64→25.93 秒/查询，比较的是论文所设 top-100 重排与去掉 DReranker 的对应整体流程，不是单次安全核验的通用耗时。p.20 §5.9 写 2 张 NVIDIA A800 80GB；p.21 紧接着重复的段落写 8 张，同指表9。无法从论文确定实际 GPU 配置，不自行择一；硬件差异使该成本难以外推。
7. **例证，p.22–23 表10。** Salvation Army 个例中，DemoRank 选到有关时间问题及正负标签不同的示例，相关性分数高于 EPR 的示例组合。它是单例解释而不是对恶意前提、事实真实性或多跳共同必要性的干预实验。
8. **作者明确的未覆盖范围，p.23。** 未来工作包括 30B/70B 规模的 LLM 与其他 passage ranking 范式，如 listwise、pairwise。文中的 list-pairwise 是**示例序列重排器的训练损失**，不应混同为 passage 本身已有 listwise/pairwise 排序评测。

## 五、与开题 A/B 的关系

参照[开题研究内容](<../../../../partitions/section3_content.tex>)：研究点一的威胁模型与问题形式化见行 15–43；研究点二的统计/语义特征、校准、跨块关系与异源参照见行 238 附近及 286–343。

| 比较项 | 存在的重合 | 关键边界和未验证问题 |
|---|---|---|
| A：同源多块协同投毒 | 都涉及多项文本的组合效用、顺序/独立评分不足，条件化选择是可借鉴的方法思想。 | DemoRank 选择的是带相关性标签的历史演示，不是攻击者改写单个真实来源后经未知分块器产生的两个互补恶意块；没有联合 Top-K、目标答案诱导、重分块鲁棒性或无/单/双块四格干预，因此不构成 A 的同型攻击，也不证明 A 新颖。 |
| B：检索上下文净化 | 都有查询条件下文本表示和重排/筛选，且说明单项分数与组合效用可能不同。 | DemoRank 的目标是排序相关性，未做恶意检测、跨来源事实支持核验、统计特征与 PCA16/随机森林融合、独立干净 query 最大风险校准，也未评估良性多跳桥接证据保留；不能把相关性得分当可信度或安全概率。 |
| B 的安全声明边界 | LLM 的选择/重排可能提示将组合效用作为探索性基线。 | 开题现有文本中的统计分支查询级校准依赖干净查询可交换条件，不能自动推及跨块关系触发率或最终 LLM 误删率；DemoRank 没有提供这些保证，也没有验证 B 的实际净化性能。 |

判断：**方法邻近、任务与威胁模型不同**。潜在撞题集中在“按已有前缀选择互补项”的通用建模思想；若开题仅表述为依赖感知选择或组合优于独立排序，须主动引用并明确差异，不能据此宣称完全首创。是否构成实质重复仍需比较 A/B 最终的目标函数、数据、验证与实现。
