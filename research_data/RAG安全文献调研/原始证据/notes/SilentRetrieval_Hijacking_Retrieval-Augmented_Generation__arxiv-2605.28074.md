# SilentRetrieval: Hijacking Retrieval-Augmented Generation via Semantically-Preserving Adversarial Data Poisoning

**定位：针对查询的单段持久语料投毒，是开题 A 的直接方法近邻；联合检索与生成防御可作 B 的对照。** 白盒检索器梯度、语义相关种子、流畅度约束和目标答案触发融合均有已有方案。此文没有在已读作者稿中验证一份真实长源经未知分块形成的同源互补块、共同召回以及逐块和联合删除后的共同必要性。其防御实验也没有报告 B 所需的干净查询级误删校准。

## 方法及攻击者能力

- **威胁模型（pp. 2–4）**：每个已知目标 query 对应生成一篇投毒文档，注入持久知识库以诱导合成目标答案。默认 seed 是该 query 的 Top-1 检索段落，长度规范为约 100±20 token。主要构造对 Contriever 使用白盒梯度；黑盒结果是代理检索器到未见目标检索器的迁移，并非只通过目标 API 的完全自适应黑盒优化。
- **两阶段（pp. 3–4）**：CBS 多位置联合优化嵌入相似度和困惑度门控，使宿主在加入负载后仍有检索机会；CATG 由固定 Llama-2-7B-Chat 生成候选触发语。NLI 门控检查触发语是否蕴含**攻击目标答案**，另检查触发语与优化文档的主题余弦相似度、整段 PPL。它们不是对原文事实真实性或完整语义等价的独立证明。PPL 阈值 50 按 NQ 良性段落确定，并固定用于 MS MARCO。
- **预算口径（p. 4）**：“每查询一篇”不意味着整个实验知识库只注入一篇；作者说明总体污染比例以所有目标 query 对应的投毒文档同时注入后计算。本文默认段落级种子与一段投毒，不是未知受害 chunker 下的真实长文档编辑实验。

## 与开题逐项比较

| 对照项 | 已读作者稿中的证据 | 研究影响 |
|---|---|---|
| A：同源长文档与未知分块 | 种子是已检索段落；按 query 生成注入文档。 | 对单段隐蔽投毒的宽泛首创表述需收窄；未知分块、单一真实源编辑仍需独立建模。 |
| A：同源互补块共同召回与必要性 | 未报告两块来自同一长源并对单块/联合删除作因果对照。 | 当前稿件未显示 A 的完整协议；不能由此宣称其他论文或正式版不存在。 |
| B：检索后检测与来源关系 | 比较 PPL、LLM、Mahalanobis 检测与重排、混合检索、隔离投票；未验证来源链、实体或命题关系。 | 同时保留轻量检测和自适应重排对照，不能将单次检测率等同来源真实性。 |
