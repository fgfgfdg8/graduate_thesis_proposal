\section{相关研究现状}

\subsection{检索增强生成技术研究现状}

检索增强生成技术的相关研究主要围绕外部知识检索与生成联合建模、检索器训练以及检索上下文组织等方面逐步发展。

领域早期研究探索了将外部知识与语言模型进行结合的模式。Guu等\cite{guu2020realm}提出的REALM将检索文档作为隐变量，用掩码语言建模任务提供训练信号，联合学习知识检索与信息利用，以增强语言模型的信息检索与利用能力；Lewis等\cite{lewis2020retrieval}明确提出了检索增强生成框架，将预训练的生成式语言模型与稠密检索器整合，将检索器上下文一并作为输入交给生成器，奠定了现代RAG系统的雏形。Izacard等\cite{izacard2021leveraging}提出的FiD则采用另一种范式，通过分别编码查询与多段证据，再由解码器通过交叉注意力融合这些表示的方式来生成答案。上述工作使外部知识能够以可检索、可更新的形式参与生成过程，为后续RAG系统的发展奠定了基础。

在知识库构建方面，RAG系统通常将原始文档进行解析、清洗和分块，来转换为可索引的检索单元。文档分块策略包括固定长度、句子或段落边界、语义分块等方式，并可进一步采用重叠窗口缓解边界截断，其中固定长度分块便于控制输入规模，按句子或段落边界分块有助于保留局部语义，重叠窗口则可以缓解分块边界造成的信息截断，分块大小、重叠长度及结构边界共同影响信息完整性和检索粒度。同一源文档产生的多个文本块可能分别包含回答所需的不同事实，也可能因重叠而重复包含相同内容\cite{gao2023retrieval}。因此，源文档到检索单元的转换并非简单截断，而会改变证据的组织方式；检索器及检索策略的设计也会进一步影响RAG系统的检索与生成性能\cite{liu2025ragsurvey,yuan2026ragoptimization}。

在文本表示与检索方面，现有的检索方式可以分为稀疏检索、稠密检索、混合检索等不同方式，其中稀疏检索依据词项匹配及统计权重衡量相关性，稠密检索通过编码器将查询与文本映射为连续向量，再根据内积或余弦相似度搜索候选，而混合检索则结合了稀疏检索与稠密检索的分数，通过加权融合的方式计算检索得分\cite{liu2025ragsurvey,yuan2026ragoptimization}。Karpukhin等\cite{karpukhin2020dense}提出的稠密段落检索（Dense Passage Retrieval，DPR）采用双编码器分别表示查询和段落，利用问答相关性标注、批内负样本及难负样本训练模型，使文档表示可以预先计算，从而支持大规模向量检索。针对批内负样本不能充分反映全库检索竞争的问题，Xiong等\cite{xiong2021approximate}提出的近似最近邻负例对比估计方法（Approximate Nearest Neighbor Negative Contrastive Estimation，ANCE）从全语料的近似最近邻索引中选取难负样本，并随训练异步更新文档表示与索引。在缺少相关性标注的场景下，Izacard等\cite{izacard2022unsupervised}提出的Contriever利用同一文档的随机裁剪片段构造正样本，并结合词元删除、动量编码器和负样本队列开展无监督对比学习；在此基础上，作者团队进一步使用微软机器阅读理解数据集（Microsoft MAchine Reading COmprehension，MS MARCO）\cite{bajaj2018msmarcohumangenerated}进行微调，获得了广泛使用的Contriever-MS稠密检索模型。从监督双编码器、全库难负样本到无监督预训练及监督微调，稠密检索形成了不同的数据依赖与匹配偏好，为后续评价攻击在不同检索器上的表现提供了基础。

在后检索阶段，系统可以结合稀疏与稠密检索结果进行混合召回，并根据任务需求对候选文本进行重排序，再按照上下文长度预算选择和排列证据，以增强检索的准确性\cite{gao2023retrieval,liu2025ragsurvey,yuan2026ragoptimization}。在典型RAG流程中，生成模型最终接收的是经过检索、排序和上下文组织后的证据集合，而非直接读取完整知识库。由此，RAG输出取决于知识库构建、文本分块、检索排序和上下文组织等环节，RAG系统的安全问题也需要相应地沿整条链路进行研究。

\subsection{检索增强生成系统投毒攻击研究现状}

现有RAG投毒攻击研究的关注点逐步由恶意文本的构造与检索排名操纵，扩展至检索与生成联合操纵，并进一步探索低投毒预算、触发式攻击、多文本组合以及受害侧分块与重排序等因素。

早期针对生成模型的攻击研究工作主要以对抗性文段生成为主。Ebrahimi等\cite{ebrahimi-etal-2018-hotflip}提出的HotFlip将输入文本序列编码为one-hot向量，利用输入梯度执行原子翻转操作，证明了在输入中仅需少量词元就可以改变NLP模型的分类结果；Wallace等\cite{wallace2019universal}提出的通用对抗触发序列通过白盒的梯度搜索构造可迁移的触发后缀，以实现将该后缀附加到不同输入上让模型稳定地产生攻击者指定的错误结果；Zou等\cite{zou2023universal}提出的通用可迁移对抗攻击方法（Greedy Coordinate Gradient，GCG）进一步结合贪心搜索与梯度估计生成对抗后缀，成为了广泛使用的白盒大模型越狱基线方法。但是，上述方法主要以攻击成功率为优化目标，生成内容可能是语义不连贯的乱码序列，在语言分布上与自然文本存在较为显著差异。Liu等\cite{liu2024autodan}在AutoDAN中指出，基于词元搜索获得的对抗性提示往往在语义上无意义，容易受到基于困惑度（Perplexity，PPL）的防御器的检测，并转而通过分层遗传搜索生成更自然的提示，以进行更隐蔽的越狱攻击。这说明，随着对抗文本优化的发展，文本自然度与语义连贯性开始成为攻击方法需要考虑的重要因素之一。

当对抗性文段生成思想引入RAG系统后，优化目标从“改变模型输出”进一步分解为“进入检索结果”和“影响最终生成”。在针对RAG系统的检索操纵研究方面，Zhong等\cite{zhong-etal-2023-poisoning}提出的对抗段落注入方法以一组训练查询为优化目标，从一个自然段落初始化出发，利用类似HotFlip的梯度搜索迭代替换离散词元，使攻击段落与查询集合的平均嵌入相似度最大化，并进一步通过聚类生成多个具有不同语义表示的攻击段落，以较少的注入样本提升其在未见查询上的 Top-$k$ 检索排名；Ben-Tov 等\cite{ben2025gasliteing}提出的GASLITE则将这一思路扩展至更严格的内容无关场景，通过基于嵌入空间梯度的搜索直接构造同时满足“携带攻击者指定信息”和“针对目标查询分布获得高检索排名”两个目标的对抗文本，而无需访问或依赖目标语料内容、修改检索模型参数，并在多种稠密检索器上取得了较强的泛化攻击能力。这类方法揭示了检索相似度和检索排名具有可操纵性，但其主要优化目标仍集中于恶意文本自身的检索竞争能力，并未充分解决恶意内容进入生成上下文后如何与正常证据竞争、如何被生成模型采信等问题。

在知识库投毒方面，已有部分先驱工作揭示了文档投毒在RAG系统中的攻击面。Zou等\cite{zou2025poisonedrag}提出的PoisonedRAG首次将知识库投毒形式化为目标查询与目标答案驱动的优化问题，并把攻击文本拆分为满足检索条件的部分和满足生成条件的部分，将检索与生成两个条件联系起来，证明了仅在百万条文本级的知识库中注入5条恶意投毒文本，即可以较高的攻击成功率操纵RAG系统在指定问题上回答攻击者设定的目标答案。Chang等\cite{chang2025oneshot}提出的AuthChain则面向单文档投毒场景，通过先从目标多跳问题中提取查询意图、关键证据节点及其关系，再利用迭代式的证据链构造与质量判别机制，将多跳推理所需的实体关系组织为一条完整、自洽的证据链，并进一步增强文档的相关性与权威性，使单个投毒文档既能够获得较高的检索排名，又能够在生成阶段压制合法知识和模型内部知识的影响，从而实现对复杂多跳问题的单文档知识投毒攻击。Zhang等\cite{zhang2026corruptrag}提出的CorruptRAG针对传统投毒攻击依赖多篇恶意文本占据检索结果的假设，将攻击预算限制为单个投毒文本，并通过联合优化文本的检索相关性与生成诱导能力，使该文本能够在目标查询下获得较高检索排名并进一步影响生成结果，从而验证单文档投毒在较低注入成本下对RAG系统实施知识操纵的可行性；Cheng等\cite{cheng2024trojanrag}提出的TrojanRAG则通过LLM生成毒化上下文、使用知识图谱做增强后，使用对比学习与正交优化联合的方式微调检索器，在检索器中植入特定的触发词后门；Chaudhari等\cite{chaudhari2026phantom}提出的Phantom则将单文档投毒进一步扩展为触发式后门攻击，首先利用嵌入空间优化构造仅在目标查询包含特定自然触发词序列时具有较高相似度的恶意文档，使其进入检索结果；随后利用多坐标梯度优化在该文档中生成能够诱导LLM执行特定攻击指令的对抗性文本，从而实现对拒答、偏见输出、隐私泄露及有害内容生成等多种生成行为的定向控制。上述工作表明，单文档投毒已从“构造完整证据链”发展到“压缩投毒预算”和“引入触发式后门”，攻击目标也从事实篡改扩展到多种生成风险；然而，该类方法虽然提高了攻击的条件选择性和行为控制能力，但攻击载荷仍主要封装在单一文本内部，对攻击语义完整性的依赖较高，尚未进一步利用多个检索单元之间的信息分工降低单个文本承担完整攻击逻辑的要求。

针对RAG系统中多文本或分布式投毒机制的研究相较于将整个文档作为投毒单元的研究仍相对有限。Nie等\cite{nie2026crcp}提出的CRCP主要关注文档级攻击信号在分块和重排序过程中的损失，指出攻击者在文档层面优化得到的信号可能被受害侧分块分散或稀释，而重排序器更偏好局部连贯且包含答案线索的文本块。CRCP将受害侧分块和重排序从攻击者不可控的预处理步骤转化为攻击优化约束，使攻击文本在经过真实处理链路后仍能保持检索竞争力，但其优化目标仍然是提高单个攻击块的独立有效性，而非利用多个同源块之间的互补关系。在分布式逻辑组合投毒方面，Zhang等\cite{zhang2026inceptionrag}提出的InceptionRAG将恶意逻辑分散到多个休眠文本中，分别构造属性文本和桥接文本并注入知识库，使目标答案通过多个文本的联合逻辑推理得到。该方法使用零阶后缀优化算法，利用神经正切核将黑盒场景下的离散词元解空间搜索近似为可求梯度的高斯过程，将攻击由显式单点注入推进到多文本逻辑组合，但其威胁模型中攻击者仍可构造并直接向语料库投入多个不同来源的独立文档，其攻击单元以独立文本形式直接注入语料库，尚未将“源文档-分块-同源检索单元”这一转换过程作为核心攻击约束进行系统建模。

综上，现有研究已经分别从检索排名操纵、知识库投毒、低预算单文档攻击、触发式后门、分块鲁棒性以及多文本逻辑组合等角度揭示了RAG系统的不同攻击面，但不同工作所假设的攻击控制对象和优化约束仍存在明显差异。已有投毒攻击研究工作大多将一篇独立文本视作一个独立的检索单元，但在典型RAG处理流程中，攻击者写入的源文档通常还需要经过受害侧分块，最终以多个文本块参与检索。因此，在攻击侧，仍存在以下尚未充分被研究的问题：当攻击者只能控制一个源文档，而无法控制受害侧的分块策略时，由该源文档产生的多个同源文本块能否分别承担互补的攻击语义、共同获得检索机会，并在生成阶段形成区别于单块投毒的联合攻击效果。针对这一问题，本文拟研究基于多文本分块协同的组合式投毒攻击框架，从源文档、受害侧分块到检索上下文的完整处理链路出发，分析单一源文档条件下多块攻击载荷的构造、检索与组合机制，并进一步刻画RAG系统在检索上下文层面的潜在安全脆弱性。

\subsection{检索增强生成系统防御研究现状}

现有RAG投毒防御研究主要围绕恶意文本检测与过滤、检索上下文结构分析、鲁棒证据聚合、检索表示空间调整、内部表征检测以及生成结果责任归因等方向展开。

在检索后到生成前阶段的文本检测与过滤方面，Kim等\cite{kim2025gmtp}提出的梯度掩码词元概率方法（Gradient-based Masked Token Probability，GMTP）先利用检索相似度对词元的梯度定位高影响位置，再以掩码语言模型评价这些词元在上下文中的条件概率，将异常检索贡献与语言合理性结合。该方法主要利用恶意文本中高影响词元与其语言合理性之间的不一致进行检测，因此当攻击文本能够通过自然语言表达同时保持较高检索贡献时，其检测依据可能相对减弱。Kim等\cite{kim2025ragdefender}提出的RAGDefender利用检索结果之间的相似性和聚集特征识别异常段落，具有较低的额外计算成本；但其检测依据依赖投毒文本在检索集合中形成可识别的分布结构，当攻击者通过多个语义互补、彼此差异较大的文本块共同实现攻击目标时，各攻击块未必足以形成明显的高相似度簇，从而削弱基于检索集合聚集结构的检测依据。

在检索上下文结构感知检测方面，Zhou等\cite{zhou2025trustrag}提出的TrustRAG同时处理文本分布异常与知识冲突，先采用聚类区分检索文本，并结合文本重合程度以降低对良性文本的误删率，再利用模型内部知识与保留的外部证据进行冲突整理和自评估，以剔除异常的投毒文本。Zheng等\cite{zheng2025grada}提出的GRADA依据文档间相似性构造加权图，通过迭代得分传播重新排序，并以查询相关性修正图中连接，对异常的投毒文本进行检测与防御。但是，这类防御方法的效果依赖上下文聚类可分性和大模型的内部知识准确性，因此在外部知识发生正常更新或模型内部知识过时时，较难以可靠方式区分“知识冲突”和“正常知识更新”；而对于正常多跳问题中的低连接桥接证据，或攻击者主动构造与正常证据保持语义联系的投毒文本，其图结构异常性减弱，这类方法的检出性能将会降低。Moradi等\cite{cegrag2026}提出的CEG-RAG进一步从检索上下文表示层面进行投毒检测，通过提取交叉编码重排序器最后一层的池化查询-文本交互表示作为检测特征，并将一次检索得到的文本块建模为一个实例集合，通过多实例学习机制，同时完成上下文级风险判断与文本块级异常定位。CEG-RAG已证明了检索上下文整体表示包含安全信息，但其建模粒度仍停留在实例级异常定位，尚未充分考虑多个文本块协同形成攻击语义这一更高层次风险。

在生成阶段的上下文鲁棒聚合方面，现有研究主要通过构造多组候选上下文、比较不同证据组合下的生成结果，并利用一致性或代表性信息降低恶意检索文本对最终答案的影响。例如，RobustRAG\cite{xiang2024certifiably}通过对检索文本进行分组并分别生成答案，再利用跨组结果进行聚合，在给定污染比例约束下提供一定的鲁棒性保证；PRA-RAG\cite{tan2026prarag}则通过构造固定规模的文本子集，对候选证据组合进行表示空间分析，选择能够覆盖多数候选组合的代表性邻域进行聚合；ShieldRAG\cite{he2026shieldrag}进一步利用滑动窗口组织多组证据生成结果，并基于共识信息调整检索表示空间，以降低异常文本对后续检索和生成过程的影响。这类方法的核心思想依赖多个检索证据之间存在一定程度的一致性，并通过跨样本聚合或表示空间约束识别非一致的潜在异常。然而，这类方法的有效性通常建立在攻击文本比例受限、干净证据占据多数以及不同证据组能够形成稳定语义共识等假设之上。当攻击者采用多个语义互补文本共同构造分布式投毒时，恶意信息可能同时出现在多个证据组合中，使异常模式由单一离群样本转变为群体性偏移，从而削弱基于一致性分析的方法效果。此外，对于需要多个文本共同提供完整推理链的正常多跳问题，强制划分证据组或限制候选组合规模可能破坏原有证据关联；同时，大规模候选组合搜索、多轮生成以及表示空间调整也会带来额外计算开销，限制了此类方法在实际RAG系统中的部署范围。

与前述主动过滤方法不同，部分工作关注错误生成发生后的责任归因与取证。Yin等\cite{yin2026rade}提出的责任感知证据解码方法，先生成临时回答，再联合估计文本对当前生成路径的有向影响及其相对共识的语义风险责任，通过排序和可靠性标记调整检索文本的影响力，以区分高影响的有害文本与正常事实桥接文本。但该方法的完整责任估计依赖于词元概率、注意力信号或代理评分器等数据，它的共识责任门控依赖正常数据校准，语料或检索器变化后仍然需要重新校准，内部一致的污染文本仍会影响风险的判断。Zhang等\cite{zhang2025traceback}提出的RAGForensics以用户报告的查询和错误回答为输入，先检索相关候选文本，再由大语言模型逐条判断文本是否支持该错误回答，移除已识别的投毒文本后继续检索，将排查范围限制在与异常事件相关的证据中。在此基础上，Zhang等\cite{zhang2026ragorigin}随后提出的RAGOrigin则从责任归因角度出发，为每次误生成构建聚焦归因域，结合检索排名、语义相关性和生成影响为候选文本分配责任分数，并通过无监督聚类隔离毒文本。这些工作建立了从错误生成结果反向定位高责任检索文本的分析范式，但主要针对攻击已经造成错误生成的事后场景，因此其目标是责任归因，而非在RAG系统生成结果前识别潜在的上下文级风险。

综合来看，现有防御方法已经从单文本异常检测逐步扩展到检索集合关系分析、鲁棒证据聚合、上下文表征建模以及生成结果责任归因，但其检测依据通常建立在恶意文本具有局部异常、集合分布异常、与正常证据缺乏关联或能够被多数正常证据抵消等假设之上。而对于分布式投毒情形，攻击者可以尝试将攻击逻辑分散到多个文本块，使各文本块分别保持较高的语义合理性和检索相关性，而攻击效果仅在多个同源文本块共同进入生成上下文后显现。在这一情况下，传统的以单块异常为主要依据的检测方法可能难以充分刻画跨块组合产生的风险，基于文本聚集或图结构的检测也可能因攻击块之间具有不同功能而难以形成稳定的异常模式，而依赖多数正常证据的鲁棒聚合则可能与正常多跳推理所需的跨文本证据组合产生冲突。因此，如何从检索上下文的整体表征出发，在不依赖单个文本块显著异常的情况下识别潜在的组合式投毒风险，是现有防御研究仍值得进一步研究的问题。
