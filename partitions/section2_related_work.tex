\section{相关研究现状}

近年的领域综述已从模型、记忆、工具和多Agent交互等层面系统归纳LLM Agent面临的安全与隐私威胁\cite{deng2025ai,he2025survey}。在评测层面，ToolEmu利用大模型模拟沙箱评估Agent工具使用风险\cite{ruan2024toolemu}，InjecAgent\cite{zhang2024injectagent}、AgentDojo\cite{balunovic2024agentdojo}、Agent Security Bench\cite{zhang2025asb}和AgentDyn\cite{li2025agentdyn}则进一步建立了面向真实Agent运行的间接提示注入攻防的专门化评估集。针对LLM Agent工具调用链的间接提示注入攻击威胁，现有防御工作大致沿着“提示工程与输入净化—训练与安全对齐—Agent系统架构设计”的技术路径演进，以下从这三个层面分别梳理现有研究工作的脉络及其局限。

\subsection{基于提示工程与输入净化的防御方法}

早期研究试图仅通过提示文本的组织方式或简单的净化规则抵御间接提示注入，其共同特点是既不改变模型参数，也不改变Agent的执行架构，而是依赖提示层面的结构调整引导模型区分指令与数据。Schulhoff\cite{schulhoff2024sandwich}提出的Prompt Sandwiching（提示夹心法）在不可信内容前后重复插入用户原始指令，试图借助模型对近端上下文的注意力偏好，使其在读取外部内容后仍能回忆并优先执行最初的任务目标。Hines等\cite{hines2024defending}提出的Spotlighting（数据分隔符法）通过对工具返回的不可信内容施加特殊分隔符标记或字符编码变换（如虚假语言编码、编码转写），使模型有机会将其显式识别为数据而非指令，从而降低对其中指令性内容的遵从概率。Shi等\cite{shi2025promptarmor}提出的PromptArmor则在数据净化侧引入了更工程化的检测流程，调用额外的现成LLM识别并移除输入中可能存在的注入指令。Zhang等\cite{zhang2025asb}提出的Agent Security Bench基准则进一步将分隔符、提示夹心法、指令预防（Instructional Prevention）、复述（Paraphrasing）与乱序（Shuffle）等同类简单方法系统化为统一的基线家族，并纳入同一评测协议中比较其防御效果。

上述方法\cite{schulhoff2024sandwich,hines2024defending,zhang2025asb,shi2025promptarmor}的安全性均建立在大语言模型对分隔符、重复指令等结构化信号的概率性遵从之上，缺乏独立于模型推理行为的确定性保障。已有攻防评测研究\cite{zhan2025adaptive,balunovic2024agentdojo,zhang2024injectagent}表明，提示工程类防御在跨任务、跨攻击策略以及面向具体防御设计的自适应载荷下表现并不稳定，其中自适应攻击可显著提高对已有防御的绕过率。因此，仅依靠提示词层面的引导尚不足以为Agent工具调用链建立可信、可验证的安全边界。

\subsection{基于训练的防御方法}

为弥补提示工程类方法的不足，已有一批研究转向通过训练或微调的方式，使大模型或专用检测器具备更稳定的指令边界识别与抗注入能力。在大模型层的安全对齐方面，Wallace等\cite{wallace2024instruction}提出的Instruction Hierarchy显式定义系统消息、用户输入与第三方工具/数据输出之间的优先级，并提出“上下文综合”与“上下文忽略”两种自动数据生成方法，训练模型在指令发生冲突时优先遵循系统级特权指令、忽略或驳回与其不一致的低特权内容。Chen等\cite{chen2025struq}提出的StruQ在LLM系统前构建前端，通过特殊标记将指令与数据分离到不同的结构化通道，并微调专门的模型识别这些标记，以降低数据被误解析为指令的概率。Chen等提出的SecAlign\cite{chen2025secalign}和Meta SecAlign\cite{chen2025metasecalign}将提示注入防御进一步形式化为偏好优化的对齐训练问题，采用直接偏好优化范式训练模型在面对含注入指令的输入时偏好安全输出、抑制不安全响应，在保持常规任务能力的同时提升对提示注入的鲁棒性。Mou等\cite{mou2026toolsafe}提出的ToolSafe框架引入基于多任务防御反馈强化学习微调的步骤级主动安全护栏模型，在每步工具调用前进行安全检查。在提示注入文本检测方面，ProtectAI\cite{protectai2024deberta}提出基于DeBERTa-v3-base微调的提示注入分类器，以较低的推理开销对输入文本进行二分类判别；Li等\cite{li2025piguard}提出的PIGuard针对已有提示注入护栏普遍存在的“过度防御”问题进行专门优化，在维持较高攻击检出率的同时降低良性任务的误报率。Liu等\cite{liu2025datasentinel}提出的DataSentinel则采用博弈论意义下的极小极大（minimax）检测训练框架，将检测器训练建模为攻击者与检测器之间的对抗博弈，以提升检测器对适应性攻击的鲁棒性。

相较于提示工程，训练类方法\cite{wallace2024instruction,chen2025secalign,chen2025metasecalign,chen2025struq}可获得更稳定的统计安全收益，但其泛化能力受限于训练分布，面对未覆盖的攻击话术时安全性无法保证；安全反馈与工具执行间仍为松耦合关系，难以形成强制约束\cite{mou2026toolsafe}；外挂式检测器\cite{li2025piguard,liu2025datasentinel}多处理孤立文本片段，尚未覆盖多轮工具调用中的跨步骤风险传播。此外，持续的模型训练与更新所需的资源投入，也制约了此类方法对快速演化攻击手段的响应速度。

\subsection{基于Agent系统架构设计的防御方法}

经典系统安全研究将最小权限与完全仲裁确立为敏感操作控制的基本原则\cite{saltzer1975protection}，并通过格模型形式化不同安全等级之间的信息流约束\cite{denning1976lattice}。在此基础上，污点分析与全系统溯源长期被用于追踪不可信数据的传播路径和关联系统事件的因果依赖\cite{pasquier2018runtime,cheng2024kairos,zipperle2022provenance}，为具有相似因果结构的LLM Agent工具调用链安全研究提供了方法论借鉴。然而，Agent场景下数据传播由概率性的自然语言推理而非语法依赖决定，传统方法难以直接迁移，因此近年研究开始关注运行时监控、执行溯源与因果归因以及架构级信息流控制三个方向，探索面向Agent工具调用链的专门化防御机制。

\textbf{运行时监控与执行环境约束。}该类工作的防御时间节点在工具调用的实际执行环节。Shi等\cite{shi2025progent}提出的Progent权限控制框架使用运行时拦截器，依据工具名及参数上的符号策略检查每次工具调用，并利用SMT求解器判定策略更新属于权限收缩还是扩张，以防止未经确认的静默权限升级。Wang等\cite{wang2025agentspec}提出的AgentSpec面向运行时约束设计领域特定语言，允许开发者将安全策略转化为形式化执行规则，并在代码执行、具身Agent等高风险场景中实施拦截。Wen等\cite{wen2026agentsys}提出的AgentSys通过显式的分层记忆管理，在隔离的子任务执行单元内对命令类工具调用触发验证器，检测到风险后净化当前观察内容，并在原意图下有界重启。也有研究\cite{wang2025cacheprune}从模型内部表示层出发，在推理时监控并编辑KV缓存中与注入指令相关的注意力模式，引导模型不遵循被识别出的注入内容，且无需重新训练。

运行时监控与执行环境约束将安全检查推进到实际动作边界，但其防御覆盖仍受策略表达能力与监控入口完整性的制约\cite{shi2025progent,wang2025agentspec,wen2026agentsys}；其中，策略生成或验证过程仍可能依赖模型判断，而CachePrune等模型内部干预又与特定推理架构及缓存实现紧密相关\cite{wang2025cacheprune}。此外，现有处置方式主要表现为拦截、净化或重启，对风险等级、动作副作用和任务连续性的联合权衡仍缺少统一机制。

\textbf{执行溯源与因果归因。}该类工作试图为Agent的运行轨迹构建可查询的溯源结构，进而定位风险的来源与传播路径。An等\cite{an2025ipiguard}提出的IPIGuard在接触外部数据前规划工具依赖图，将任务执行建模为图上的受约束遍历，并通过节点扩展与参数估计适应执行中的动态信息，以避免注入内容引入计划外工具调用。Wang等\cite{wang2025agentarmor}提出的AgentArmor将Agent运行时轨迹抽象为程序依赖图，并引入安全类型系统进行细粒度信息流控制与策略检查。Wang等\cite{wang2026authgraph}提出的AuthGraph构建授权图与溯源图相结合的双图架构，以参数策略约束关键参数的允许来源，并将动态重规划限制在白名单与程序检查范围内。Cai等\cite{cai2026ghost}提出的NeuroTaint离线审计器将关注点从语法依赖的信息流传播转向基于语义转换与因果推理的传播，通过动态上下文溯源图在Agent记忆边界和会话重启后维持污点谱系，并引入汇点驱动的因果分析器，以反事实推理捕捉隐式控制流影响。Sequeira等\cite{sequeira2026agentsentry}提出的Agent-Sentry从Agent历史良性轨迹中学习正常行为边界，构建“结构分类器初判—白名单参数来源过滤—LLM残余仲裁”的三层运行时门控架构，将大部分判定固化在确定性结构检查中。Zhang等\cite{zhang2026agentsentry}提出的AgentSentry针对工具返回边界设计受控的反事实模拟执行机制，在不提交真实副作用的前提下判断工具返回内容是否驱动后续风险行为，并通过因果门控净化上下文后继续任务。Kim等\cite{kim2026causalarmor}提出的CausalArmor对特权决策执行留一法（Leave-One-Out）意义下的归因分析，仅在观测到不可信内容对决策产生主导性影响时触发针对性净化。

上述方法能够刻画注入攻击在Agent轨迹中的结构特征，但检测能力与闭环处置之间仍存在落差。在溯源可信度方面，部分依赖关系推断或残余仲裁过程仍需借助LLM\cite{wang2026authgraph,sequeira2026agentsentry}，可能引入推断误差或二次注入风险；不同方法中的授权与来源证据也尚缺少统一的外部验证方式。在处置闭环方面，已有工作\cite{cai2026ghost,zhang2026agentsentry,kim2026causalarmor}多聚焦于检测、归因或恢复的某一环节，风险定位、阻断、恢复与切断验证的联合效果尚缺少统一评测。

\textbf{架构级信息流控制与确定性授权。}针对运行时方法在安全保证上的概率性局限，一系列工作从系统架构层面重新设计Agent的执行模型，试图以确定性机制取代概率性过滤。Debenedetti等\cite{debenedetti2025camel}提出的CaMeL采用规划与执行分离的双LLM架构，特权规划器仅读取用户提示生成数据流图，被隔离的执行器严格按图调用工具，从架构层面阻断不可信数据对控制流的劫持。Wu等\cite{wu2024fsecure}提出的f-secure LLM系统从信息流控制视角出发，将LLM系统解耦为具备上下文感知能力的处理管线，并依据信息流控制原则动态生成结构化执行方案，以限制不可信数据对控制流的影响。Costa等\cite{costa2025fides}提出的FIDES将信息流控制方法应用于Agent，为内容附带完整性与机密性标签并强制传播，在敏感工具执行前对不可信数据进行隔离提取与策略门控。Kim等\cite{kim2025promptflow}提出的Prompt Flow Integrity借鉴系统安全中的最小权限原则，将Agent拆分为分别处理可信与不可信数据的双组件，通过跨组件通信监控与显式、隐式流检查，在不可信数据流向敏感汇聚点时触发告警或阻断。

架构级方法通过确定性地重构执行模型增强了安全约束的强度，但代价集中在额外执行器带来的计算开销与效用损失\cite{debenedetti2025camel}、信息流控制难以覆盖隐式控制流\cite{costa2025fides}、以及数据来源与信任等级标注的质量直接制约安全性等方面\cite{kim2025promptflow,wu2024fsecure}。整体而言，此类方法的安全保证仍受标注质量、策略完备性与部署复杂度的共同制约。

\textbf{面向授权判定与反馈处置的防御机制。}在通用运行时约束之外，另有一批工作将“当前动作是否符合用户任务”和“判定异常后如何继续执行”作为核心问题。Wu等\cite{wu2025isolategpt}提出的IsolateGPT采用中心节点与隔离执行单元相结合的架构，将第三方应用限制在独立环境中，并通过受信接口和用户许可仲裁跨应用交互。Li等\cite{li2025drift}提出的DRIFT仅依据用户请求预先生成最小工具轨迹与参数检查表，再由动态验证器根据任务意图和操作权限审查执行偏移，并通过注入隔离器净化冲突指令。Jia等\cite{jia2025task}提出的Task Shield在测试阶段逐项验证指令和工具调用是否服务于用户目标，对不一致动作返回反馈并要求Agent重新规划。Zhu等\cite{zhu2025melon}提出的MELON通过掩码用户请求后重执行Agent轨迹，比较原始执行与掩码执行中的工具调用相似性，据此识别并阻断受注入任务主导的动作。Fan等\cite{fan2026granularity}提出的PACT从工具函数签名中合成参数角色契约，并跨步骤追踪参数值来源，在调用前逐参数核验来源可信度。Santos-Grueiro\cite{santosgrueiro2026temporary}提出的Commit-Time Authorization将授权依据、当前派生状态与持久化效果绑定，在提交前核验授权新鲜度和效果一致性。Liu\cite{liu2026toolconnectionexecutioncontrol}提出的HCP将主体、授权、能力与数据管道对象化，并通过执行控制不变量为工具调用的允许或拒绝提供审计依据。

现有工作已将防御边界从输入检测推进到动作授权与执行反馈，但各自仍覆盖不同的局部环节：IsolateGPT侧重第三方应用隔离与跨域仲裁，尚未直接刻画用户任务级的动态授权边界\cite{wu2025isolategpt}；DRIFT依赖预先生成的轨迹与检查表，Task Shield依赖语义层面的任务一致性判断，而MELON的掩码重执行会引入额外推理开销\cite{li2025drift,jia2025task,zhu2025melon}。PACT、Commit-Time Authorization与HCP进一步细化了参数来源、提交效果和执行不变量，但均属于近期预印本，其跨框架有效性仍需独立评测验证\cite{fan2026granularity,santosgrueiro2026temporary,liu2026toolconnectionexecutioncontrol}。因此，如何在同一机制中联合任务级授权、跨步骤证据传播、动作反馈与安全续接，仍有进一步研究空间。

综上所述，现有LLM Agent工具调用链间接提示注入攻击防御方法沿提示工程、训练对齐与系统架构三条路径演进，呈从概率性过滤逐渐转向体系性约束的发展趋势，前两类方法部署成本较低，但安全性较多依赖模型的概率性遵从；架构类方法约束力更强，却伴随较高的部署与维护负担；部分工作虽已覆盖检测、授权、归因或恢复中的多个环节，但授权判定、跨步骤传播遏制与执行恢复的联合效果仍缺少统一评测，对拒绝反馈披露粒度与任务效用之间关系的经验研究亦不充分。上述不足，为本研究从任务契约驱动的调用前防御与轨迹图驱动的在线检测恢复两个研究方向展开提供了动机。
