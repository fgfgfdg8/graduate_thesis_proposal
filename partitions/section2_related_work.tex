\section{相关研究现状}

检索增强生成系统通过外部知识补充模型的参数化知识，其安全研究涉及知识获取、文档处理、文本分块、检索排序和生成证据利用等环节。已有工作由单条恶意文本的检索与诱导，逐步发展到分块条件下的攻击优化和多文本联合投毒；防御研究则围绕异常检测、证据聚合及生成影响分析展开，为研究同源文本块协同攻击及其防御提供了基础。

\subsection{检索增强生成技术研究现状}

检索增强生成技术的研究围绕如何让语言模型稳定利用外部知识展开，其发展脉络可以概括为检索与预训练联合建模、稠密检索训练、多阶段上下文组织三个阶段。

在外部知识与语言模型结合方面，Guu等\cite{guu2020realm}提出的REALM将检索文档作为隐变量，用掩码语言建模任务提供训练信号，联合学习知识检索与信息利用。Lewis等\cite{lewis2020retrieval}提出的RAG框架将预训练的序列生成模型与稠密检索器连接，在检索到的候选文档上对生成概率进行边际化。Izacard等\cite{izacard2021leveraging}提出的FiD分别编码查询与多段证据，再由解码器通过交叉注意力联合利用这些表示。上述工作使外部知识由静态训练语料扩展为可检索、可更新的证据来源，但检索到的文本能否构成完整一致的生成依据，仍取决于证据的选择与组织。刘雪颖等\cite{liu2025ragsurvey}将RAG流程归纳为索引、检索和生成三个基本环节，并指出检索与生成的协同仍是复杂任务中的薄弱环节；袁乐等\cite{yuan2026ragoptimization}从优化角度进一步分析了RAG各环节及其相互关联，指出了检索器、检索策略增强对RAG系统性能提升具有重要的作用。

在知识库构建方面，原始文档通常经过解析、清洗和分块，转换为可索引的检索单元。文档分块策略主要分为固定长度分块和重叠分块两种策略，其中固定长度分块便于控制输入规模，按句子或段落分块有助于保留局部语义，重叠分块可以缓解边界截断，分块大小、重叠长度及结构边界共同影响信息完整性和检索粒度。张犬俊等\cite{zhang2026ragsoftware}结合软件工程应用总结了知识库构建、检索和生成三个阶段的挑战，并指出多粒度检索与结果重排序会影响检索结果的相关性和多样性。同一源文档产生的多个文本块可能分别包含回答所需的不同事实，也可能因重叠而重复包含相同内容\cite{gao2023retrieval}。因此，源文档到检索单元的转换并非简单截断，而会改变证据的组织方式。

在文本表示与检索方面，稀疏检索依据词项匹配及统计权重衡量相关性，稠密检索通过编码器将查询与文本映射为连续向量，再根据内积或余弦相似度搜索候选。Karpukhin等\cite{karpukhin2020dense}提出的稠密段落检索（Dense Passage Retrieval，DPR）采用双编码器分别表示查询和段落，利用问答相关性标注、批内负样本及难负样本训练模型，使文档表示可以预先计算，从而支持大规模向量检索。针对批内负样本不能充分反映全库检索竞争的问题，Xiong等\cite{xiong2021approximate}提出的近似最近邻负例对比估计方法（Approximate Nearest Neighbor Negative Contrastive Estimation，ANCE）从全语料的近似最近邻索引中选取难负样本，并随训练异步更新文档表示与索引。在缺少相关性标注的场景下，Izacard等\cite{izacard2022unsupervised}提出的Contriever利用同一文档的随机裁剪片段构造正样本，并结合词元删除、动量编码器和负样本队列开展无监督对比学习；Contriever-MS则在同一工作的监督适配设置中，使用微软机器阅读理解数据集（Microsoft MAchine Reading COmprehension，MS MARCO）\cite{bajaj2018msmarcohumangenerated}继续微调模型。从监督双编码器、全库难负样本到无监督预训练及监督微调，稠密检索形成了不同的数据依赖与匹配偏好，为后续评价攻击在不同检索器上的表现提供了基础。

在后检索阶段，系统可以结合稀疏与稠密检索结果进行混合召回，并根据任务需求对候选文本进行重排序，再按照上下文长度预算选择和排列证据\cite{gao2023retrieval,liu2025ragsurvey,yuan2026ragoptimization}。生成模型最终读取的是经过筛选的检索上下文，而非完整源文档。由此，RAG输出取决于知识库构建、文本分块、检索排序和上下文组织等环节，RAG系统的安全问题也需要相应地沿整条链路分析。

\subsection{检索增强生成系统投毒攻击研究现状}

RAG投毒攻击的研究脉络可以概括为：由面向检索排名的对抗文本构造，发展到面向生成结果的知识腐蚀，再进一步转向单文档攻击、分块感知优化和分布式逻辑组合。

在对抗后缀生成方面，Ebrahimi等\cite{ebrahimi-etal-2018-hotflip}提出的HotFlip利用one-hot输入梯度执行原子翻转，以少量词元修改改变分类结果；Wallace等\cite{wallace2019universal}提出的通用对抗触发序列通过梯度搜索构造可迁移的触发文本；Zou等\cite{zou2023universal}提出的通用可迁移对抗攻击方法（Greedy Coordinate Gradient，GCG）进一步结合贪心搜索与梯度估计生成对抗后缀，并在多个模型之间验证了迁移性。上述方法主要以攻击成功率为优化目标，生成内容可能语义不连贯，并在语言分布上与自然文本存在差异。Liu等\cite{liu2024autodan}在AutoDAN中指出，基于词元搜索的提示往往语义无意义，容易受到基于困惑度（Perplexity，PPL）的检测，并转而通过分层遗传搜索生成更自然的提示。这说明，随着对抗文本优化的发展，文本自然度与语义连贯性开始成为攻击方法需要考虑的因素。

在检索操纵方面，Zhong等\cite{zhong-etal-2023-poisoning}提出的对抗段落注入方法利用检索器梯度优化离散词元，从而提高攻击段落与目标查询的相似度；Ben-Tov等\cite{ben2025gasliteing}提出的GASLITE进一步研究携带指定内容的高排名文本构造，并在多种嵌入模型和攻击知识条件下评价检索脆弱性。这类方法揭示了用户查询与检索语料库文本的相似度可以被操纵，但其优化目标集中在检索排名，注入文本能否被生成模型采信，还取决于攻击信息的表达以及正常证据的竞争。此外，面向检索器的离散词元优化通常在单条攻击文本上独立进行，尚未涉及同一源文档经分块后多个检索单元之间的协同关系。

在知识库投毒方面，已有部分先驱工作揭示了文档投毒在RAG系统中的攻击面。Zou等\cite{zou2025poisonedrag}提出的PoisonedRAG将知识库投毒形式化为目标查询与目标答案驱动的优化问题，并把攻击文本拆分为满足检索条件的部分和满足生成条件的部分，设置了黑盒与白盒两种条件。该工作将检索与生成两个条件联系起来，并在少量注入文本与大规模知识库的实验中验证了攻击影响。Chang等\cite{chang2025oneshot}提出的AuthChain进一步将投毒文档数量缩减为一个，先根据查询抽取证据节点与关系，再构造覆盖这些信息的完整证据链。该方法说明单个文档可以承载多跳问题所需的诱导内容，但其证据链在源文档层面组织，在经过RAG系统分块后各检索单元能否保留不同角色，仍然是一个开放问题。Song等\cite{song2026adversarialcot}提出的AdversarialCoT则针对推理型模型构造单文档攻击，先提取目标模型的推理框架，据此生成查询相关的对抗性思维链（Chain-of-Thought，CoT），再根据模型反馈调整文档中的相关性线索或证据顺序，以提高投毒效率。但是，该方法依赖可观察的回答或推理反馈，并通过多轮调整提高攻击效果，计算代价较高；其优化对象仍是单份文档中的推理诱导内容，尚未分析文档分块后的多单元协同作用。

在分块感知投毒方面，Nie等\cite{nie2026crcp}提出的CRCP关注文档级攻击信号在分块和重排序过程中的损失，指出攻击者在文档层面优化得到的信号可能被受害侧分块分散或稀释，而重排序器更偏好局部连贯且包含答案线索的文本块。CRCP将分块变换显式纳入攻击优化，并联合考虑稠密检索相关性、重排序得分和块边界鲁棒性，使每个攻击文本块尽可能独立保持有效。然而，该工作的目标侧重单个文本块在完整处理链路中的稳定性，强调的是单块投毒，而非多块的分布式协同作用。在重排序器条件下的投毒方面，Yang等\cite{yang2026p3a}提出的提示扰动投毒攻击（Prompt-Perturbation Poisoning Attack，P3A）针对重排序器在检索结果过滤中的盲点，先通过规则化提示工程构造初始投毒文本，再注入约1\%的字符级扰动，以提高文本在重排序器中的排名，同时保持攻击语义和文本可读性。该方法在单文档投毒条件下仍取得较强的攻击效果和迁移能力，说明重排序器并非投毒攻击的可靠屏障，攻击优化需要同时考虑检索、重排序与生成三个阶段。在分布式逻辑组合投毒方面，Zhang等\cite{zhang2026inceptionrag}提出的InceptionRAG将恶意逻辑分散到多个休眠文本中，分别构造属性文本和桥接文本并注入知识库，使目标答案通过多个文本的联合逻辑推理得到。该方法使用零阶后缀优化算法，并借鉴神经正切核与高斯过程代理建模历史奖励，以进行黑盒场景下的解空间搜索，将攻击由显式单点注入推进到多文本逻辑组合，但其威胁模型中攻击者仍可构造并直接向语料库投入多个不同来源的独立文档，而忽略了实用RAG系统中的检索分块流程，不能有效保证在不同的分块配置下，成对的投毒文档都能保证良好的检索和攻击语义。因此，本研究关注攻击者仅控制一个源文档，由受害侧分块器自然产生多个同源文本块，并在问题检索过程中进行同源召回与答案生成这一更贴近真实威胁模型的攻击面。

综上所述，现有攻击研究已经分别解决了少量恶意文本操纵检索、单文档知识腐蚀、分块与重排序条件下的攻击保持以及多文本分布式逻辑诱导等问题，但控制对象和优化目标并不统一；对于仅能写入一个源文档的攻击者，文档数量压缩并不意味着攻击单元只有一个：在真实的RAG系统中，源文档并不是直接的检索单元，而是往往先经过受害侧的分块策略分块后，形成多个检索单元，然后才进入检索召回过程中。这些同源文本块能否分别承担互补语义角色、共同进入Top-K检索结果，并通过跨块组合产生单块条件下不出现的生成效果，仍缺乏针对性的系统分析。针对这一问题，本文拟提出基于多文本分块协同的组合式投毒攻击框架，以实际分块结果、联合召回和组合式生成攻击成功率为评价对象，研究单一源文档在受害侧处理链路中的攻击机制。

\subsection{检索增强生成系统防御研究现状}

RAG防御研究的分析对象沿着文本单元、文本关系、上下文表征和生成影响逐层扩展，相关方法主要包括检索后过滤、检索上下文结构与自评估、鲁棒聚合、嵌入空间调整、内部表征检测以及事后取证等方向。

在检索后到生成前阶段的文本检测与过滤方面，Kim等\cite{kim2025gmtp}提出的梯度掩码词元概率方法（Gradient-based Masked Token Probability，GMTP）先利用检索相似度对词元的梯度定位高影响位置，再以掩码语言模型评价这些词元在上下文中的条件概率，将异常检索贡献与语言合理性结合。该方法适合识别依靠局部词元扰动提升排名的文本，但其应用需要访问检索器梯度，检测依据也与高贡献词元的语言异常有关；语句流畅但通过多个文本块共同形成误导的内容，难以仅依靠单块语言异常识别。Kim等\cite{kim2025ragdefender}提出的RAGDefender先根据检索集合的分布估计可疑段落数量，再统计段落在高相似文本对中的出现频次，并按相似度加权排序以实施过滤。该方法已经利用文本之间的关系，且避免额外的大语言模型推理与检索器重训练。扩大检索段落数量时其性能可能出现波动，对持续形成密集簇的对抗段落也缺少理论保证。因此，相似性集中可以提供检测线索，但面对语义互补、未形成紧密簇的攻击文本，还需考察其联合生成作用。

在检索上下文结构与自评估方面，Zhou等\cite{zhou2025trustrag}提出的TrustRAG先采用聚类区分检索文本，并结合文本重合程度降低误删率，再利用模型内部知识与保留的外部证据进行冲突整理和自评估。该方法同时处理文本分布异常与知识冲突，防御效果因而与聚类可分性和内部知识准确性有关。对于需要利用新近外部知识的问题，模型自身的判断也需要接受证据支持检查，避免将知识更新误判为冲突。Zheng等\cite{zheng2025grada}提出的GRADA依据文档间相似性构造加权图，通过迭代得分传播重新排序，并以查询相关性修正图中连接，对异常的投毒文本进行检测与防御。该方法的出发点是部分攻击文本虽然与查询高度匹配，却与正常证据联系较弱；通过扩大候选检索规模保留正常文本多数，再利用图中的连接关系调整排名，即可对孤立攻击文本实施过滤。但该策略依赖正常证据的可获得性，图连接强弱本身也不等同于证据可信度，正常多跳问题中的桥接文本也可能与其他证据仅有局部联系，不能独立形成可靠的结构评分。

在上下文鲁棒聚合方面，Xiang等\cite{xiang2024certifiably}提出的RobustRAG将检索文本划分为互不重叠的组，分别生成回答，再通过关键词或逐词元概率聚合得到结果。在污染段落数量有界等条件下，该方法为部分查询提供回答质量下界，其保证也覆盖知晓防御的自适应攻击者。采用分组隔离策略可以限制恶意证据的影响范围，但正常多跳证据被分入不同组时，单组生成可能缺少必要信息，因此分组粒度既影响安全保证，也影响跨文本证据的完整利用；同时，分组生成和判断引入了额外的延迟与计算开销，难以适用于实时性敏感的在线问答系统。Tan等\cite{tan2026prarag}提出的PRA-RAG在检索集合中构造固定大小的文本子集，将子集内各段表示按顺序拼接，并依据角距离寻找覆盖多数候选组合的较小邻域，选取代表性组合用于聚合，以保证依赖干净子集在检索集合的全部候选组合中占多数，以降低污染数据对生成过程的影响。但是这一条件同时受污染段落数、检索规模和子集大小影响；面对较大的组合空间，还必须采用采样近似以控制计算开销，在可扩展性和精度方面存在一定局限性。

在嵌入空间特征调整方面，He等\cite{he2026shieldrag}提出的ShieldRAG采用滑动窗口组织多组检索证据，分别生成答案与解释，再聚合回答中的共识关键词；当共识不足时，则根据解释中的语句或短语调整查询，使后续检索更加接近正常证据。过程通过多数共识对证据进行调整，将偏离正常证据的文本推离、将一致证据拉近，从而在检索和生成之间形成迭代调整。但是，该机制强依赖于可形成共识的回答信息，并引入了多组生成及查询更新的额外延时与计算开销；当少数关键桥接证据与多数证据不一致时，共识聚合可能削弱其作用，而在投毒信息较多的高污染条件下，共识质量也会迅速下降，影响该方法的可靠性。

在注意力机制内部表征检测方面，Moradi等\cite{cegrag2026}提出的CEG-RAG提取交叉编码器重排序器的末层表示，将检索上下文作为样本集合、文本块作为集合中的实例，采用多实例学习（Multiple-Instance Learning，MIL）完成上下文判断与块级定位。该方法通过集合编码对文本块间的交互关系建模，训练时使用上下文级标签，并在检测到风险后删除可疑块、补入低风险候选。但该方法依赖访问重排序器内部激活值，且集中于一种投毒攻击和固定检索生成配置，对于单块正常、组合后产生误导的分布式投毒情形，泛化能力仍缺乏证据。

在生成影响分析与事后取证方面，Yin等\cite{yin2027rade}提出的责任感知证据解码方法，先生成临时回答，再联合估计文本对当前生成路径的有向影响及其相对共识的语义风险责任，通过排序和可靠性标记调整检索文本的影响力，以区分高影响的有害文本与正常桥接文本。但该方法的完整责任估计还需要词元概率、注意力信号或代理评分器；它的共识责任门控依赖正常数据校准，语料或检索器变化后仍然需要重新校准，内部一致的污染文本仍可能影响风险判断。Zhang等\cite{zhang2025traceback}提出的RAGForensics以用户报告的查询和错误回答为输入，先检索相关候选文本，再由大语言模型逐条判断文本是否支持该错误回答，移除已识别的投毒文本后继续检索，将排查范围限制在与异常事件相关的证据中。但是，该方法属于攻击后的来源定位与修复，实时防御仍需结合检索前的风险审查与生成阶段的证据控制。

综上所述，已有防御已从单段异常扩展到文本关系、上下文检测、鲁棒聚合与生成影响分析，部分方法也显式考虑了正常桥接证据。然而，多数方法仍以单段异常或可分离的污染集合为重要前提；对于同一源文档经受害侧分块形成的多个语义互补文本块，局部异常可能较弱，块间关系也可能接近正常多跳推理，现有方法仍缺乏针对性的系统分析。针对这一问题，本文拟研究基于检索上下文表征分析的安全防御方法，综合单块表征、跨块关系和上下文整体分布，在降低攻击成功率的同时，保持正常检索与生成效用，以保护RAG系统的安全性和可靠性。
