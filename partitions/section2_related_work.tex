\section{相关研究现状}

检索增强生成系统通过外部知识补充模型的参数化知识，其安全研究涉及知识获取、检索结果组织和生成证据利用等环节。已有工作逐步从单条恶意文本的检索与诱导，发展到分块条件下的攻击优化和多文本联合投毒。防御研究则围绕异常检测、证据聚合及生成影响分析展开，为研究同源文本块协同攻击及其防御提供了基础。

\subsection{检索增强生成技术研究现状}

在外部知识与语言模型结合方面，Guu等\cite{guu2020realm}提出的REALM将检索文档作为隐变量，用掩码语言建模任务提供训练信号，联合学习知识检索与信息利用。其检索索引随编码模型异步更新，使模型在预训练、微调和推理阶段访问外部文档。该工作说明，知识可以通过可更新的文档库参与模型预测，但其原始任务主要围绕掩码预测和开放域问答展开，生成式回答中的多证据组织仍需专门设计。

Lewis等\cite{lewis2020retrieval}提出的RAG框架将预训练的序列生成模型与稠密检索器连接，在检索到的候选文档上对生成概率进行边际化。该框架分别考虑整段输出使用同一文档和不同词元利用不同文档的生成方式，将检索选择与回答生成联系起来。Izacard等\cite{izacard2021leveraging}提出的FiD则将查询与各段证据分别编码，再由同一解码器对全部编码表示进行交叉注意力计算。原文在评测范围内观察到增加检索段落数量带来的问答收益，说明多个证据单元的联合利用是影响生成质量的因素。相应地，检索到相关文档并不等于模型已获得完整且一致的回答依据，证据的选择与组织仍会改变生成结果。

在知识库构建方面，原始文档通常经过解析、清洗和分块，转换为可索引的检索单元。固定长度分块便于控制输入规模，按句子或段落分块有助于保留局部语义，重叠分块可以缓解边界截断。分块大小、重叠长度及结构边界共同影响信息完整性和检索粒度。同一源文档产生的多个文本块可能分别包含回答所需的不同事实，也可能因重叠而重复包含相同内容\cite{gao2023retrieval}。

在文本表示与检索方面，稀疏检索依据词项匹配及统计权重衡量相关性，稠密检索通过编码器将查询与文本映射为连续向量，再根据内积或余弦相似度搜索候选。2020年，Karpukhin等\cite{karpukhin2020dense}提出的稠密段落检索（Dense Passage Retrieval，DPR）采用双编码器分别表示查询和段落，利用问答相关性标注、批内负样本及难负样本训练模型。文档表示可以预先计算，从而支持大规模向量检索。该路线减少了对字面重合的依赖，但检索效果受到监督数据和负样本质量的影响。针对批内负样本不能充分反映全库检索竞争的问题，Xiong等\cite{xiong2021approximate}提出的近似最近邻负例对比估计方法（Approximate Nearest Neighbor Negative Contrastive Estimation，ANCE）从全语料的近似最近邻索引中选取难负样本，并随训练异步更新文档表示与索引。该方法使训练阶段接触到模型在实际检索中容易混淆的文本。其改进重点在于监督训练中的负样本选择，模型的检索偏好仍与训练查询及索引更新方式有关。

在缺少相关性标注的场景下，Izacard等\cite{izacard2022unsupervised}提出的Contriever以及Contriever-MS利用同一文档的随机裁剪片段构造正样本，并结合词元删除、动量编码器和负样本队列开展无监督对比学习。该方法将稠密检索的训练来源扩展到未标注文档，并在跨数据集检索中评价表示的迁移能力。为考察监督适配的作用，该研究还利用微软机器阅读理解数据集（Microsoft Machine Reading Comprehension，MS MARCO）\todo{这里需要增加对原论文的引用}继续微调模型。由监督双编码器、全库难负样本到无监督预训练及监督微调，稠密检索的发展形成了不同的数据依赖与匹配偏好，安全实验需要据此区分检索模型和训练配置\todo{这句话表述太生硬}。

在多阶段检索与上下文组织方面，混合检索方式通过将词项匹配与语义匹配的候选或得分融合，来获得更好的检索性能。部分系统\todo{这里引用1篇正式发表文献，没有证据则删掉，重排序器不是本文的主要研究对象}在初步召回后使用交叉编码器重排序器，对查询与文本进行细粒度交互评分，再按照上下文长度预算选择和排列证据。生成模型最终读取的是经过筛选的检索上下文，而非完整源文档，稀疏检索、稠密检索、混合检索和重排序可以根据任务需求组合\cite{gao2023retrieval}。因此，本文的安全评价将从源文档分块、文本块检索、重排序保留和生成证据利用等RAG管线的不同环节切入，分析不同环节对攻击效果的影响。

\subsection{检索增强生成系统投毒攻击研究现状}

在知识库投毒与检索操纵方面，Zhong等\cite{zhong-etal-2023-poisoning}首先提出的对抗段落注入方法利用检索器梯度优化离散词元，从而提高攻击段落与目标查询的相似度；Ben-Tov等\cite{ben2025gasliteing}提出的GASLITE则进一步研究携带指定内容的高排名文本构造，并在多种嵌入模型和攻击知识条件下评价检索脆弱性。这类方法揭示了用户查询与检索语料库文本的相似度可以被操纵的新攻击面，而高排名文本能否进一步使生成模型采信指定内容，还取决于攻击信息的表达及正常证据的竞争。Zou等\cite{zou2025poisonedrag}提出的PoisonedRAG首次将知识库投毒形式化为目标查询与目标答案驱动的优化问题，并把攻击文本拆分为满足检索条件的部分和满足生成条件的部分，设置了黑盒与白盒两种条件，黑盒设置通过前置目标查询增强相关性，白盒设置进一步利用检索器梯度信息优化文本。生成诱导部分由辅助语言模型构造并检查，使注入内容能够支持指定答案\todo{这句话太生硬，修改}。该工作将检索与生成两个条件联系起来，验证了仅需少量文本注入（5条）即可对大规模知识库（百万条级）造成显著的影响。不过，PoisonedRAG构造恶意文本时，仍然以文档级为单位，以每条恶意文档独立满足这两个条件为目标，尚未专门分析同一源文档经系统分块后，多个互补文本块共同作用的情形。Chang等\cite{chang2025oneshot}提出的AuthChain则进一步缩减投毒文档的数量，仅利用1个投毒文档，先根据查询抽取证据节点与关系，再构造覆盖这些信息的完整证据链，并通过伪造的机构背书与时效性陈述提高文本的表面可信度。该方法在一份攻击文档中同时处理检索匹配、证据完整性和模型采信问题，说明单文档也能承载多跳问题所需的诱导内容。其完整证据链在源文档层面组织，分块后各检索单元是否保留不同角色、能否共同进入上下文，仍依赖结合实际分块过程评价\todo{这句话太生硬，修改}。

Song等\cite{song2026adversarialcot}提出的AdversarialCoT则进一步针对推理型模型构造单文档攻击，该方法先提取目标模型的推理框架，据此生成查询相关的对抗性思维链（Chain-of-Thought，CoT），再根据模型反馈调整文档，当文档未被检索时则修改相关性线索，被检索但未诱导目标回答时则调整证据顺序和推理衔接；实验结果表明，通过多轮交互性的调整能够改善攻击效果，但也会增加模型调用和长上下文处理成本。该方法依赖可观察的回答与推理反馈，其优化重点是单份文档中的推理诱导\todo{这句话太生硬，与前文衔接不流畅，而且没有客观评估这个研究工作的缺陷}。

在分块感知的RAG文本投毒方面，Nie等\cite{nie2026crcp}提出的CRCP则将文本分块视为优化过程中的变换，针对多种块长与随机边界偏移评价攻击文本，并联合考虑稠密检索相关性、重排序得分和局部语义完整性。其主要设置借助代理模型优化，另提供仅能访问评分时的黑盒近似方式。该工作揭示了文档级相似度与最终上下文保留之间的差异，要求局部文本同时包含查询相关信息、答案线索和攻击引导，以减少分块造成的信号损失。该目标侧重单个投毒文本块在处理链路中的稳定性，但是该研究局限于将所有投毒载荷聚焦于单个文本块中，无法逃避基于文本块级检测的识别机制，相比分布式投毒的隐蔽性更弱。在分布式与组合式投毒方面，Zhang等\cite{zhang2026inceptionrag}提出的InceptionRAG率先探索了利用代理实体，构造属性文本与桥接文本分别注入知识库，使目标答案通过跨文本推理得到的投毒方案。其检索增强步骤在文本首尾加入查询相关线索，生成诱导步骤则使用零阶后缀优化（Zeroth-Order Suffix Optimization，ZOSO）算法，依据历史评价奖励，建立使用神经正切核（Neural Tangent Kernel，NTK）的高斯过程（Gaussian Process，GP）代理，将离散的文本解空间搜索任务映射到连续可微嵌入空间的方式，在候选后缀的表示空间中提出更新方向，以搜索合适的权威性与推理引导后缀，通过代表性查询子集与分阶段后缀搜索共同减少了逐候选、逐查询穷举的计算开销。该工作把跨文本逻辑联系与黑盒优化成本纳入攻击设计，但依旧依赖构造不同源的多个独立文档实施投毒攻击，且忽略了实际RAG系统中，文档被分块后载荷的有效性，且对依赖来源校验的防御易感。

综上所述，现有攻击已覆盖少量文本操纵、单文档诱导、分块与重排序适应以及分布式逻辑组合，但这些工作的控制对象与优化目标仍然存在差异，存在隐蔽性不足、威胁模型不够现实等问题。对于仅能写入一个源文档的攻击者，文本块的数量与边界由受害者侧处理过程决定，源文档修改会同时影响角色保持、联合召回与生成关系。由此，本文将研究重点进一步推进到单一源文档经分块产生不同独立检索单元，通过同源互补块的联合召回及它们共同影响回答的机制上，以揭示实用RAG系统尚未被充分研究的新威胁面。本研究拟围绕这一约束，建立一个基于多文本分块协同的组合式投毒攻击框架，在每次候选评价中执行实际分块，以联合召回与组合式生成作为相联系的目标，并通过独立查询和受控上下文实验分析攻击效果。

\subsection{检索增强生成系统防御研究现状}

在检索后文本检测与过滤方面，Kim等\cite{kim2025gmtp}提出的梯度掩码词元概率方法（Gradient-based Masked Token Probability，GMTP）先利用检索相似度对词元的梯度定位高影响位置，再以掩码语言模型评价这些词元在上下文中的条件概率。该方法将异常检索贡献与语言合理性结合，适合识别依靠局部词元扰动提升排名的文本，但是其应用需要访问检索器梯度，检测依据也与高贡献词元的语言异常有关，语句流畅但通过跨块关系形成的误导则需要补充组合层面的评价，针对分布式、离散化的投毒攻击防御仍有局限性。Kim等\cite{kim2025ragdefender}提出的RAGDefender先根据检索集合的分布估计可疑段落数量，再统计段落在高相似文本对中的出现频次，并按相似度加权排序以实施过滤。该方法已经利用文本之间的关系，且避免额外的大语言模型推理与检索器重训练。原文指出，扩大检索段落数量时性能可能波动，对抗段落持续形成密集簇也缺少理论保证。因此，相似性集中可以提供检测线索，但面对语义互补、未形成紧密簇的攻击文本，还需考察其联合生成作用\todo{太生硬，逻辑断裂，改}。

在投毒溯源与事后取证方面，Zhang等\cite{zhang2025traceback}提出的RAGForensics以用户报告的查询和错误回答为输入，先检索相关候选文本，再由大语言模型逐条判断文本是否支持该错误回答，移除已识别的投毒文本后继续检索，将排查范围限制在与异常事件相关的证据中，以减少搜索盲目性；其判断依赖已知错误输出，作为一种事后审计手段，主要服务于攻击后的来源定位与修复，更适合作为一种补充性的防御与审计措施。

综上所述，已有防御已从单段异常扩展到文本关系、上下文检测与修复，部分方法也显式考虑了生成影响和正常桥接证据。面向同源多文本块攻击，仍需检验局部异常较弱的组合能否进入审查范围、组合依赖如何与正常多跳推理区分，以及修复后新形成的证据组合是否仍有风险。针对这些问题，本研究拟结合单块表征、跨块关系与上下文整体分布，在有限预算下开展组合影响审查，并通过证据选择和修复后复查同时评价攻击抑制效果与正常问答效用。
