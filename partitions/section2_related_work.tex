\subsection{LLM Agent间接提示注入攻击威胁现状}
\todo{补全这一块内容以体现文献脉络，补全文献内容和文脉，大致是：Prompt Injection → Jailbreak/Instruction Hijacking → Indirect Prompt Injection → Tool/Agent Manipulation → Multi-Agent / Workflow-Level Attack → Adaptive Agent Exploitation}
间接提示注入攻击由Greshake等\cite{greshake2023notwhat}于2023年首次提出，其核心威胁在于攻击者将恶意指令嵌入Agent可能通过工具读取的外部数据源（如网页、邮件、文档），从而在Agent推理上下文中注入非预期指令，劫持后续工具调用行为。该发现暴露了LLM Agent场景下“数据与指令边界模糊”的根本安全隐患。此后，攻击手法沿多个维度迅速演化：

\textbf{（1）工具选择与调用劫持。} 攻击者可诱导Agent选择攻击者指定的恶意工具\cite{shi2026pitoolselection}，或在已授权工具上以不当方式使用其功能\cite{zhang2026evaluatingprivilege}，使原本合理的工具权限被用于恶意目的。

\textbf{（2）多步组合攻击。} Kothamasu等\cite{kothamasu2026hidden}指出，攻击者无需单条指令实现全部恶意目标，而是将恶意意图拆分为多个看似合法的子任务，散布在不同工具返回内容中，利用Agent的多步规划能力自动拼接成完整攻击链，使得检测与防御更加困难。

\textbf{（3）信息泄露与系统侦察。} 通过对抗性提示或角色扮演，攻击者可诱导Agent泄露系统提示词、上下文记忆或内部策略，暴露其安全边界与任务目标\cite{hui2024scp}；同时，越狱方法（如角色扮演、社会工程学）能绕过模型的安全对齐，将有害内容生成进一步转化为实际动作\cite{shen2024do,zeng2024howjohnny2}。

\textbf{（4）供应链与后门注入。} 攻击者还可向Agent的长期记忆、检索知识库或训练数据植入投毒样本或后门触发器，使Agent在特定条件下持续输出被操纵信息或执行恶意行为\cite{chen2024agentpoison,bi2024backdoor}，构成更为持久的威胁。

上述攻击形态表明，LLM Agent的安全问题已从单点提示注入演变为覆盖工具选择、权限控制、多步逻辑组合及供应链的系统性挑战，成为后续防御研究关切的核心问题之一。

\subsection{基于提示工程与输入净化的防御方法}

早期研究试图仅通过提示文本的组织方式或简单的净化规则抵御间接提示注入，其共同特点是既不改变模型参数，也不改变Agent的执行架构，而是依赖提示层面的结构调整引导模型区分指令与数据。Schulhoff\cite{schulhoff2024sandwich}提出的Prompt Sandwiching（提示夹心法）在不可信内容前后重复插入用户原始指令，试图借助模型对近端上下文的注意力偏好，使其在读取外部内容后仍能回忆并优先执行最初的任务目标。Hines等\cite{hines2024defending}提出的Spotlighting（数据分隔符法）通过对工具返回的不可信内容施加特殊分隔符标记或字符编码变换（如虚假语言编码、编码转写），使模型有机会将其显式识别为数据而非指令，从而降低对其中指令性内容的遵从概率。Shi等\cite{shi2025promptarmor}提出的PromptArmor则在数据净化侧引入了更工程化的检测流程，调用额外的现成LLM识别并移除输入中可能存在的注入指令。Zhang等\cite{zhang2025asb}提出的Agent Security Bench基准则进一步将分隔符、提示夹心法、指令预防（Instructional Prevention）、复述（Paraphrasing）与乱序（Shuffle）等同类简单方法系统化为统一的基线家族，并纳入同一评测协议中比较其防御效果。

上述方法\cite{schulhoff2024sandwich,hines2024defending,zhang2025asb,shi2025promptarmor}的安全性均建立在大语言模型对分隔符、重复指令等结构化信号的概率性遵从之上，缺乏独立于模型推理行为的确定性保障。已有攻防评测研究\cite{zhan2025adaptive,balunovic2024agentdojo,zhang2024injectagent}表明，提示工程类防御在跨任务、跨攻击策略以及面向具体防御设计的自适应载荷下表现并不稳定，其中自适应攻击可显著提高对已有防御的绕过率。因此，仅依靠提示词层面的引导尚不足以为Agent工具调用链建立可信、可验证的安全边界。

\subsection{基于训练的防御方法}

为弥补提示工程类方法的不足，已有一批研究转向通过训练或微调的方式，使大模型或专用检测器具备更稳定的指令边界识别与抗注入能力。在大模型层的安全对齐方面，Wallace等\cite{wallace2024instruction}提出的Instruction Hierarchy显式定义系统消息、用户输入与第三方工具/数据输出之间的优先级，并提出“上下文综合”与“上下文忽略”两种自动数据生成方法，训练模型在指令发生冲突时优先遵循系统级特权指令、忽略或驳回与其不一致的低特权内容。Chen等\cite{chen2025struq}提出的StruQ在LLM系统前构建前端，通过特殊标记将指令与数据分离到不同的结构化通道，并微调专门的模型识别这些标记，以降低数据被误解析为指令的概率。Chen等提出的SecAlign\cite{chen2025secalign}和Meta SecAlign\cite{chen2025metasecalign}将提示注入防御进一步形式化为偏好优化的对齐训练问题，采用直接偏好优化范式训练模型在面对含注入指令的输入时偏好安全输出、抑制不安全响应，在保持常规任务能力的同时提升对提示注入的鲁棒性。Mou等\cite{mou2026toolsafe}提出的ToolSafe框架引入基于多任务防御反馈强化学习微调的步骤级主动安全护栏模型，在每步工具调用前进行安全检查。在提示注入文本检测方面，ProtectAI\cite{protectai2024deberta}提出基于DeBERTa-v3-base微调的提示注入分类器，以较低的推理开销对输入文本进行二分类判别；Li等\cite{li2025piguard}提出的PIGuard针对已有提示注入护栏普遍存在的“过度防御”问题进行专门优化，在维持较高攻击检出率的同时降低良性任务的误报率。Liu等\cite{liu2025datasentinel}提出的DataSentinel则采用博弈论意义下的极小极大（minimax）检测训练框架，将检测器训练建模为攻击者与检测器之间的对抗博弈，以提升检测器对适应性攻击的鲁棒性。

相较于提示工程，训练类方法可获得更稳定的统计安全收益，但其泛化能力受限于训练分布，面对未覆盖的攻击话术时安全性无法保证；部分工作\cite{mou2026toolsafe}的安全反馈与工具执行间仍为松耦合关系，难以形成强制约束；外挂式检测器\cite{li2025piguard,liu2025datasentinel}多处理孤立文本片段，尚未覆盖多轮工具调用中的跨步骤风险传播。此外，持续的模型训练与更新所需的资源投入，也制约了此类方法对快速演化攻击手段的响应速度。

\subsection{基于Agent系统架构设计的防御方法}

经典系统安全研究将最小权限与完全仲裁确立为敏感操作控制的基本原则\cite{saltzer1975protection}，并通过格模型形式化不同安全等级之间的信息流约束\cite{denning1976lattice}。污点分析与溯源分析则用于追踪不可信数据传播和系统事件间的因果依赖\cite{pasquier2018runtime,cheng2024kairos,zipperle2022provenance}，为具有相似因果结构的LLM Agent工具调用链安全研究提供了方法论借鉴。然而，Agent场景下数据传播由概率性的自然语言推理而非语法依赖决定，传统方法难以直接迁移，因此近年研究开始关注运行时监控、访问控制与最小权限、信息流与状态隔离、执行遏制等层次\cite{ling2026toward}。

Xiang等\cite{xiang2025guardagent}提出的GuardAgent将自然语言安全请求和目标Agent运行日志转换为动作计划与护栏代码，通过执行代码判定并拒绝违规动作。Jia等\cite{jia2025task}提出的Task Shield则逐项检查指令和工具调用是否服务于用户目标，并向Agent反馈不一致动作以触发工具调用动作的修正。An等\cite{an2025ipiguard}提出的IPIGuard在读取外部数据前规划工具依赖图，将任务执行约束为工具依赖图图上的拓扑遍历，并通过参数估计与只读节点扩展适应动态信息，以规避工具越权调用的问题。虽然这类方法已将防御边界推进到Agent运行时的动作管控，但许多研究\cite{xiang2025guardagent,jia2025task,li2025drift,zhu2025melon}仍依赖模型生成的计划、语义判定或额外重执行，导致额外的计算开销与任务延迟，降低了Agent任务的可用性；部分工作\cite{shi2025progent,fan2026granularity}虽强化了参数级的结构约束，但是其参数策略构造、契约合成和来源推断仍是实现防御的关键前提，现有机制的授权依据分散于安全请求、预期轨迹、任务一致性和参数来源，尚未形成统一的版本化任务授权闭包，对拒绝反馈披露粒度的安全与效用影响也缺少统一的建模与比较。Wu等\cite{wu2025isolategpt}提出的IsolateGPT采用中心节点与隔离执行单元构成的Hub-and-Spoke架构，将第三方应用限制在独立环境中，并通过受信接口和用户许可中介跨应用交互。Debenedetti等\cite{debenedetti2025camel}提出的CaMeL将只接触可信用户请求的特权规划器与处理不可信数据的隔离模型分离，由自定义解释器维护数据流图，并在工具调用时执行基于能力的安全策略。面向结构化权限约束，Shi等\cite{shi2025progent}提出的Progent依据工具名和参数上的符号策略实施调用前检查，并以SMT求解器区分权限收缩与需显式批准的扩张，防止静默权限升级。\todo{分析ACE的机制}Li等\cite{li2026ace}提出的ACE先使用可信信息生成抽象执行计划，再将其映射为具体应用计划，通过静态分析核验用户指定的信息流约束，并在执行阶段设置数据与能力屏障，以防御攻击者的非授权工具调用。\todo{分析这篇直接竞争工作}Fan等\cite{fan2026granularity}提出的PACT则进一步按参数角色追踪跨步骤来源，并执行参数级信任契约，以试图从细粒度的参数控制角度发现提示注入。这类架构通过可信规划、静态验证与隔离执行提供了更强的系统性约束，但安全保证依赖规划输入、策略与能力标签的正确性以及全部跨域交互均被防御层完全中介。Zhu等\cite{zhu2025melon}提出的MELON则通过中性化指令掩码用户请求，进行影子重执行，比较重执行分支与主分支的动作一致性来识别间接提示注入对Agent控制流的劫持，一旦重执行分支执行了外部注入指令而非预设的掩码指令则检测到提示注入攻击。He等\cite{he2026attriguard}提出的AttriGuard则在MELON的基础上进一步引入动作级因果归因，通过构建一个独立于主Agent执行的影子分支，并采用三个分层的LLM重写操作符改写外部通道的输入信息构造分层控制衰减视图，以反事实因果干预的方式修改影子分支的输入信息并校验其与主分支的一致性以检测提示注入攻击，。Zhang等\cite{zhang2026agentsentry}提出的AgentSentry则在工具返回边界开展受控反事实重执行，定位上下文主导决策的时点，并通过因果门控净化上下文以继续任务。

\todo{这几种方法归类说清楚，出现在这里逻辑脉络不顺}虽然文献\cite{an2025ipiguard,wang2025agentarmor}的工作已经证明基于图结构依赖结构与反事实诊断可用于刻画跨步骤注入影响，但是它们要么依赖LLM的提前规划控制流，要么依赖LLM推断隐式的控制流和信息流依赖，这会导致一定的不可靠性；这些防御框架本身的隔离组件、附加模型调用与解释执行也带来额外的部署和性能开销。同时，它们的重点在于限制预先建模的据流与能力边界，尚未在同一机制中联合可验证的运行证据、路径级阻断、受影响状态恢复与切断结果验证，对污染已跨多步传播后的路径定位、状态恢复和切断效果验证覆盖有限。

综上所述，现有LLM Agent工具调用链间接提示注入攻击防御方法沿提示工程、训练对齐与系统架构三条路径演进，呈从概率性过滤逐渐转向体系性约束的发展趋势，前两类方法部署成本较低，但安全性较多依赖模型的概率性指令遵从；架构类方法约束力更强，却伴随较高的部署与维护负担；部分工作虽已覆盖检测、授权、归因或恢复中的多个环节，但授权判定、跨步骤传播遏制与执行恢复的联合效果仍缺少统一评测，对拒绝反馈披露粒度与任务效用之间关系的研究尚不充分。上述不足，为本研究从任务契约驱动的调用前防御与轨迹图驱动的在线检测恢复两个研究方向展开提供了动机。
